# artboard 视频安全区(字幕带 · 平台 UI 遮挡)

> **何时读**:做视频场景卡(模式 S,`animation.md §〇`)、口播桥信息卡、教程/图解动画卡时**必读**;
> 或出任何会被叠字幕的动图/卡片。
> **一句话**:卡上内容**不得进入字幕带与平台 UI 遮挡带**——否则成片里被字幕/按钮/文案栏盖住。
> 数据来源:`CutFlow` 技能(用户既有资产)+ 2026 平台实测,详见 §7。

---

## 一、为什么这是硬规则,不是"注意一点"

字幕与平台 UI 是**外部叠加层**,在 artboard 里看不见、导出后必然出现。三类事故:

1. **字幕盖内容**:卡片底部放要点/落款 → 成片被字幕条压住,读不出来。
2. **平台按钮盖内容**:竖屏右侧是点赞/评论/分享按钮列(宽 180px),放文字/人脸必被盖。
3. **横向不统一**:同一条内容发抖音安全,发 Reels 被啃掉一半(Reels 底部遮挡比抖音多 100px)。

**判定口径**:内容"安全"= 落在**可用区**内,不是"画布内"。画布内 ≠ 安全。

---

## 二、安全区三档(标准 / 紧凑 / 极限)

> 三档是**同一件事的三个空间预算**。默认标准档;内容装不下才**逐级降级**,
> 每降一级都有明确代价,而且**必须把降级决定告诉用户**。
> 降级顺序:先精简/拆卡 → 紧凑档 → 极限档。**禁止不声明就直接贴边。**

| 档 | 一句话 | 代价 |
|---|---|---|
| **标准**(默认) | 跨平台保守交集,一版通吃 | 可用区最小,内容要精炼 |
| **紧凑** | 垂直方向压到有依据的下限,**左右不动** | 跨平台通吃性下降(按主发平台算) |
| **极限** | 四边统一 **2.5%**,几乎贴画布边 | **字幕与平台按钮会盖住边缘内容** |

### 2.1 标准档(默认;跨平台交集)

#### 9:16 竖屏 1080×1920(抖音 / Reels / Shorts / 视频号)

| 方向 | 保留 | px | 说明 |
|---|---|---|---|
| **顶部** | **12%** | **230** | 状态栏 + 关注/推荐标签栏 |
| **底部** | **30%** | **576** | 字幕带 + 文案栏 + 音乐行 + 播放条(最凶的 Reels 实测 500px) |
| **左** | **17%** | **184** | 与右对称留白 |
| **右** | **17%** | **184** | **平台按钮列**(点赞/评论/分享),TikTok 实测最宽 180px |

**可用区**:`x ∈ [184, 896]`, `y ∈ [230, 1344]` → **712 × 1114**

```css
:root{
  --sa-top: 230px; --sa-bottom: 576px; --sa-side: 184px;
}
.safe{
  position: absolute;
  left: var(--sa-side);  right: var(--sa-side);
  top:  var(--sa-top);   bottom: var(--sa-bottom);
  /* 所有内容放这里面;装饰元素可越界但透明度 ≤0.5 */
}
```

#### 16:9 横屏 1920×1080(B站 / YouTube / 横版教程)

| 方向 | 保留 | px | 说明 |
|---|---|---|---|
| **顶部** | **10%** | **108** | title-safe 80% 传统 + 平台标题栏 |
| **底部** | **16%** | **173** | 字幕带 + 播放进度条/控制栏 |
| **左/右** | **8%** | **154** | 横屏无按钮列,但保留 title-safe 余量 |

**可用区**:`x ∈ [154, 1766]`, `y ∈ [108, 907]` → **1612 × 799**

#### 3:4 竖屏 1080×1440(小红书图文/视频)

| 方向 | 保留 | px | 说明 |
|---|---|---|---|
| **顶部** | **10%** | **144** | 平台顶栏 |
| **底部** | **18%** | **259** | 小红书**底部无评论遮挡带**,故比 9:16 浅 |
| **左/右** | **7%** | **76** | 无右侧按钮列 |

### 2.2 紧凑档(内容较多时)

**核心取舍:垂直方向可以压,水平和底部 9:16 不能压。**

- **9:16 左右仍是 17%(184px)**——右侧平台按钮列是硬约束,压不下去;
  左侧保持对称(否则画面显偏心)。
- 顶部可压到 7%,底部压到 25%(字幕带的保守下限,再压就会与字幕重叠)。
- 横屏与小书左右没有按钮列,故可一起压到 5%。

| 画幅 | 顶 | 底 | 左右 | 可用区(标准 → 紧凑) | 增益 |
|---|---|---|---|---|---|
| **9:16** 1080×1920 | 134(7%) | 480(25%) | **184(17%)** | 712×1114 → **712×1306** | 高 +17% |
| **16:9** 1920×1080 | 76(7%) | 130(12%) | 96(5%) | 1612×799 → **1728×874** | 宽 +7% 高 +9% |
| **3:4** 1080×1440 | 101(7%) | 187(13%) | 54(5%) | 928×1037 → **972×1152** | 宽 +5% 高 +11% |

```css
/* 紧凑档:只改垂直 */
.safe{ position:absolute; left:184px; right:184px; top:134px; bottom:480px; }
```

**适用**:要点 5–7 条、口播桥文字较多、图解卡步骤多。
**要求**:交付时说明"按主发平台(如抖音)算的安全区,发到 Reels 底部可能被文案栏盖到"。

### 2.3 极限档(内容极多,几乎贴边)

四边统一 **2.5%**(可在 2%–3% 间微调,越接近 3% 越稳):

| 画幅 | 顶 | 右 | 底 | 左 | 可用区 |
|---|---|---|---|---|---|
| **9:16** 1080×1920 | 48 | 27 | 48 | 27 | **1026×1824** |
| **16:9** 1920×1080 | 27 | 48 | 27 | 48 | **1824×1026** |
| **3:4** 1080×1440 | 36 | 27 | 36 | 27 | **1026×1368** |

```css
/* 极限档:四边 2.5%,几乎贴着画布边 */
.safe{ position:absolute; inset:2.5%; }   /* inset 不支持百分比简写时用 px */
```

**代价(交付时必须明说)**:
- 底部只剩 48px(9:16)→ **字幕几乎必然盖住底部内容**;
- 右侧只剩 27px → **平台按钮列会压住右侧内容**;
- 这不是"更紧凑的排版",是**用可见性换空间**。

**使用纪律**:
1. **先试别的**:内容装不下时,优先「精简文案 → 拆成两张卡 / 两页 → 换更饱满的布局」。
   拆卡永远比贴边稳——贴边是"内容都在但都被盖",拆卡是"内容都看得见"。
2. **关键信息不下放**:即使走极限档,**主标 / 主视觉 / CTA 仍应留在紧凑档范围内**;
   只有次要内容(来源注、脚注、装饰性文字、水印)才允许进入 2.5% 边带。
3. **必须告知用户**:交付时列出"本卡用了极限安全区,字幕/按钮会盖住边缘内容"。
4. **能给出字幕就给出**:若同时交付字幕文件,把字幕下沉到边缘内容之上,
   或让字幕错开内容所在的那一侧。

### 2.4 换算公式(非 1080 基准时)

```
px = 该边百分比 × 该边像素
标准  9:16 顶 12%  底 30%  左右 17%      16:9 顶 10%  底 16%  左右 8%     3:4 顶 10% 底 18% 左右 7%
紧凑  9:16 顶  7%  底 25%  左右 17%      16:9 顶  7%  底 12%  左右 5%     3:4 顶  7% 底 13% 左右 5%
极限  四边统一 2.5%
```
百分比按**对应边**算:顶部/底部用 H,左右用 W。

### 2.5 机检(别靠肉眼)

```bash
python scripts/check_overflow.py <项目>/src --safe-area 9x16                    # 标准档
python scripts/check_overflow.py <项目>/src --safe-area 9x16 --safe-tier tight  # 紧凑档
python scripts/check_overflow.py <项目>/src --safe-area 9x16 --safe-tier extreme # 极限档
python scripts/check_overflow.py <项目>/src --safe-inset 48,27,48,27            # 自定义(上右下左)
python scripts/check_overflow.py <项目>/src --safe-area auto                    # 按画布比例判画幅
```

它按**渲染后的真实几何**算安全区(不依赖你传的画布尺寸),输出:
- 四边保留 px 与可用区尺寸;
- 每个越界元素的方向与超标 px;
- `data-allow-overflow` 的装饰豁免。

退出码 0/1,已接进流水线 **Step 6**(见 `pipeline.md`)。

## 三、平台单发明细(2026 实测,按需取用)

> 本节数值是 **§2.2 紧凑档的取值依据**,也用于"只发一个平台"时进一步省空间。
> ⚠️ 注意各平台的**右侧**普遍 ≥130px:即使只发一个平台,右侧也压不到 60px。

### 9:16 —— 只发一个平台时可放宽

| 平台 | 顶 | 底 | 左 | 右 |
|---|---|---|---|---|
| 抖音 / TikTok | 140 | 400 | 60 | **180** |
| TikTok Spark Ads(带常驻 CTA) | 150 | 400 | 60 | 140 |
| Instagram Reels | 140 | **500** | 60 | 130 |
| YouTube Shorts | 160 | 320 | 60 | 150 |
| 视频号 | 130 | 480 | 97 | 97 |

**取交集（§二）= 顶 230 / 底 576 / 左右 184**,原因:
- 顶部取 12%(230)而非各平台的 100–160px——顶部还有"关注/推荐"标签栏,且 12% 是三平台通吃的安全线;
- 底部取 30%(576)覆盖 Reels 的 500px 最凶值;
- 左右取 184px 覆盖 TikTok 的 180px 按钮列——**这是最容易被忽略的一条**。

### 16:9 —— 平台遮挡主要在垂直方向

| 平台 | 顶 | 底 | 左右 |
|---|---|---|---|
| B站 | 86 | 173 | 96 |
| YouTube | ~110 | ~170 | ~110 |

横屏左右几乎无遮挡;主要是**底部进度条 + 字幕**。

## 四、字幕带本身:内容与字幕如何共存

字幕**必须**占据底部安全带以上,内容**必须**避开它。两者关系:

```
┌───────────────────────┐ 0
│      顶部安全区 12%     │
├───────────────────────┤ 230px  ← 内容可用区上界
│                       │
│    内容可用区          │
│    (712 × 1114)       │
│                       │
├───────────────────────┤ 1344px ← 内容可用区下界
│  ↑ 字幕带顶(约 1290px)│
│     字幕                 │
│  底部安全区 30%         │
└───────────────────────┘ 1920px
```

**字幕带参数**(CutFlow 口径,仅作避让参考,artboard 不生成字幕):

| 规格 | 9:16 | 3:4 | 16:9 |
|---|---|---|---|
| 字号 | 78 | 72 | 64 |
| 底边距 marginV | 500(≈26%) | 400 | 120 |
| 单行字数上限 | 12 | 15 | 22 |
| 行数上限 | 2 | 2 | 2 |
| 语速上限 CPS | ≤9 字/秒 | ≤9 | ≤9 |

**内容与字幕的三种关系**(按优先级):

| 方案 | 做法 | 适用 |
|---|---|---|
| **① 完全避开**(默认) | 内容全在可用区内,字幕带留空 | 信息卡、图解卡、口播桥 |
| **② 让位**(内容多时) | 内容压到中上部,底部 30% 纯留白或极低透明度装饰 | 长文案卡 |
| **③ 字幕下沉**(外部协作) | artboard 出字幕版,由 CutFlow 把字幕临时降透明度/下沉 | 已与 CutFlow 联动的场景 |

**禁止**:内容与字幕"错开半行"——观感最差(既不整齐也读不清),要么完全在字幕带之上,要么完全避开。

## 五、模式 S 骨架里的落地

`animation.md §十二` 的骨架把安全区作为**画布内的一层约束**,不靠"记住":

```html
<div class="poster">              <!-- 1080×1920 -->
  <div class="bg">…</div>          <!-- 装饰层:可越界,透明度 ≤.5 -->
  <div class="safe">               <!-- 内容层:所有内容必须在这里面 -->
    <h1 class="title">…</h1>
    <div class="card">…</div>
  </div>
</div>
```
```css
.safe{
  position:absolute; left:184px; right:184px; top:230px; bottom:576px;
  display:flex; flex-direction:column; justify-content:center;
  /* 用 flex 居中而非 fixed 定位,内容多少都稳(见 card-layout.md) */
}
```

**要点**:
1. **两层分离**:`.bg` 装饰可越界(它的越界是设计),`.safe` 内容绝不越界。
2. **用 flex 居中**代替逐个 `top:` 定位——内容行数变化时自动保持居中。
3. **`.safe` 内部不要再用绝对定位**贴底——改成 `justify-content: space-between` 或 `gap`,否则又跑回安全区外。

## 六、自检(出图/出片前逐条过)

1. **跑机检**:`python scripts/check_overflow.py <项目>/src --safe-area 9x16` → `ok:true`
   (这一步是**必跑**,已接进流水线 Step 6;靠肉眼看不出线条相近时的越界)。
2. **叠安全区遮罩看**:把 `.safe` 之外涂成 50% 灰,读导出图确认**无任何文字/关键图形**落在灰区。
3. **右侧 184px 是否真的空着**(9:16)——最容易漏的一条,尤其"logo 放右下"的写法。
4. **底部 576px 是否真的空着**(9:16)——放"扫码关注""落款"必被字幕盖。
5. 装饰元素越界了但透明度 ≤0.5?(可以)
6. 横屏:底部 16% 内有没有放小字注释/来源注?(要移进可用区)
7. 跨平台发布时,用的是 §2.1 标准档,而不是 §三 的宽松值?
8. **若用了紧凑/极限档**:是否①有正当理由(确实装不下,而非图省事)②交代了代价
   ③关键信息(主标/主视觉/CTA)仍在紧凑档范围内?

> 打分走 `design-review-rubric.md`;安全区违规按「B 排版质量」扣 1–2 分,内容被字幕完全遮挡按硬伤计 0。
> **降级档的扣分口径**:标准档违规照常扣;**已声明并交代代价**的紧凑/极限档不额外扣分
> (那是用户认可的设计决策);**未声明的**贴边按"构图留白"扣分。

## 七、数据来源与漂移声明

> 下表路径**均相对 CutFlow 技能根**(不是本技能的路径)。

| 数据 | 来源 | 置信度 |
|---|---|---|
| 9:16 顶 12% / 底 30%(标准档) | CutFlow `rules/artboard.md` + ADR-0009 | 高(用户既有资产,实测) |
| 9:16 左右 17% / 各平台明细 | 2026 平台实测汇总(CreaMate 2026-07、safearea.video 2026) | 中(两源有差异,已取交集) |
| 3:4 三边 | CutFlow `templates/platforms.json`(小红书) | 高 |
| 16:9 三边 | CutFlow B站预设 + title-safe 80% 传统 | 中(横屏平台实测数据稀缺) |
| 字幕字号/marginV | CutFlow 的 `rs_subtitle.py` · `STYLES` 常量表 | 高(可直接引用) |
| 紧凑档底 25% | CutFlow 字幕禁入带口径(比各平台实测宽松值更保守) | 中高 |
| 极限档四边 2.5% | **工程取值,非实测** —— 2%–3% 区间由用户提出 | 低(是取舍,不是标准) |

**漂移警告**:平台 UI 会随 App 版本变化,实测值之间已有 ±50px 差异(如 Reels 底部 420 vs 500)。
因此**默认一律用 §2.1 标准档**;只在 §2.2/§2.3 的正当理由下降级,并交代代价。
每季度复核一次;收到"内容被盖"的反馈时,**先把档位退回上一级**(极限→紧凑→标准)再查别的。

**关于极限档的定位**:2.5% 不是任何平台的规范值,而是**当内容量与画布尺寸冲突到无法调和时的
兜底手段**。它的存在是为了让"必须排下"的场景有个明确、可机检、代价已知的出口,
而不是让安全区变得可有可无。**能用标准档就不要用极限档。**
