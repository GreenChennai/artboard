# artboard 多稿同出协议(multi-draft)

> ⚠️ **备选模式(Opt-in):默认单稿。** 本册**不在默认流水线上**——只有用户显式要求
> (「多出几版」「给我 4 个方案」)、说轻量指令(`多稿` / `出 4 稿`),或对提议答「要」时才启用。
> 没被触发就自作主张出多稿 = 白烧 token + 打乱用户预期的交付节奏,违反本册第一原则(§0)。

> **何时读**:用户要「多出几版 / 给几个方案 / 一次出 4 稿让我选 / 像 AI 绘图那样出 4 张」时,**读一次即可,本轮不重读**(读取纪律,省 token)。

## 单一真相源声明(防多真相源)

- **本册只讲**:多稿的**触发闸门**(什么时候可以出)、**受控变体**(怎么变才有鉴别力)、**联络表**(怎么一表看全)、**选择与转正**(选完怎么办)、**成本治理**(怎么不翻 4 倍)。
- **不重复、不另立**:三个方向怎么「想」仍归 `design-thinking.md` §六;改稿中途选方向的**兜底呈现**仍归 `revision-protocol.md` §5;自检时机与定点改纪律仍归 `pipeline.md` Step 6(铁律 5 不变);变体各维的具体规则归各自真相源(`composition.md` / `style-system.md` / `effects.md` / `depth-3d.md`)。本册是「批量出稿与选择」的流程协议,不是第二套设计规则。

---

## §0 第一原则:这是「按需的点菜」,不是「默认的套餐」

> **默认流水线永远是一稿**(`pipeline.md` 不动)。多稿是用户点的那道菜。
> 触发后的 4 稿**不是** 4 个完整度相同的稿子,而是**同一份内容在 4 个方向上的快速预览**——
> 内容一致、完整度一致、分辨率可低(scale 1);差异**必须一句话说得清**(「这版靠留白 / 这版靠对比 / 这版靠概念」)。
> **说不清差异的 4 稿等于重做 4 次**,是浪费。
> **禁止**:未触发就出多稿——既烧 token,也打乱交付节奏;也**禁止**把本册当默认流程读。

## §1 触发闸门(唯一的启动方式)

> **默认:单稿。** 只有以下四种情形进入多稿,其余一律单稿。

| 触发方式 | 例子 / 形态 | 动作 |
|---|---|---|
| ① 用户显式要求 | 「多出几版」「给我 4 个方案」「一次出四稿」「像 AI 绘图那样出 4 张让我选」「出个 A/B/C/D」 | **立即进入多稿**,稿数默认 4 |
| ② 轻量指令 | 会话里说 `多稿` / `多稿 4` / `出 4 稿` / `批量方案` | **立即进入多稿**,稿数按指令(N 默认 4) |
| ③ 追问时被问到 | `intake.md` 可选第 6问(仅提议一次):「要不要一次给 4 个方向供你选?」 | **仅提问不执行**;用户答「要」才进多稿 |
| ④ 兜底提议 | `revision-protocol.md §5` 诊断失败(用户反复说不清) | Agent **主动提议**「出 4 版给你指」,用户同意才执行 |

**反触发条件(即使命中上面也不出多稿)**:

| 情形 | 处置 | 理由 |
|---|---|---|
| 用户同时说「直接做 / 只要一版」 | **单稿** | 尊重用户明示节奏,多稿即过度交付 |
| 模式 B(图片复刻)/ C(换风格) | **默认单稿** | 视觉基准已在图里/任务本身是换装,多稿稀释比对精度;除非同一句里明确要「多版对照」 |
| 改稿阶段(已有成稿) | **0 稿**,定点改(`pipeline.md` 改稿协议) | 改稿不重跑是全库纪律;方向拿不准走 `revision-protocol.md` |
| 用户只表达「不够满意」(未要求多稿) | 走 `revision-protocol.md` 诊断,**不自动出多稿** | 模糊愿望先诊断;多稿是兜底提议(④),不是第一反应 |

> **闸门一句话**:「用户要了吗?(显式要求 / 指令 / 同意提议)」——要了就做,没要就单稿。

## §2 变体维度表(怎么「受控地」变)

> **纪律**:每稿只沿**一个主轴**变化,其余保持一致;4 稿合起来覆盖 4 条不同轴。
> **禁止每稿都变所有维度**——那不是 4 个方向,是重做 4 次,成本翻 4 倍且用户无法指认差异。

| 变体 | 主轴 | 具体做法(定点) | 一句话性格 |
|---|---|---|---|
| **A** | **构图/骨架** | 换 `composition.md` 骨架(三分 ↔ 中轴 ↔ 对角…) | 「结构不同」 |
| **B** | **配色/气质** | 换 `style-system.md` tokens(暖纸 ↔ 紫夜 ↔ 促红…) | 「颜色不同」 |
| **C** | **主视觉手段** | 换 `effects.md` / `depth-3d.md` 的手段(留白主导 ↔ 伪3D ↔ 大字报) | 「主角怎么出场」 |
| **D** | **大胆程度** | 保守(稳) ↔ 激进(一处主导动作,取法 `design-thinking.md` §二) | 「敢不敢」 |

**组合策略**:4 稿各取一条轴;若 brief 已锁定某维度(如「必须是深色」),则该维固定、沿其余轴变化(**可 3 稿**)。铁律 3 对每一稿单独生效:层级 ≤3 / 强调 ≤2 / 特效 ≤3 / 字体 ≤3——多稿不放宽任何上限。

## §3 四稿性格标签(给用户可指认的名字)

| 稿 | 标签 | 特征 | 何时会被选 |
|---|---|---|---|
| **A 稳** | 保守正确 | 最稳妥的解,兜底 | 要「不出错」 |
| **B 雅** | 编辑/留白 | 大留白 + 克制 | 要「高级 / 简约」 |
| **C 冲** | 冲击/大字报 | 强对比 + 主导动作外放 | 要「抓眼 / 促销」 |
| **D 巧** | 概念/意外 | 一个巧思装置 | 要「有记忆点」 |

> 标签写进联络表(`--label` 叠 A/B/C/D 字母;一句话性格写进交付消息与字母对应,或用 `imageops.py watermark` 预烧进单图)——用户「指一个字母」即可,比让他描述容易一个数量级。

## §4 制作流程(第 0 步先确认触发,共 6 步,低成本)

```bash
S="<skill>/scripts"
# 0) 前置:确认已触发(用户要求 / 指令 / 同意提议);未触发不做本流程
# 1) 建 1 次项目(内容结构只写一次)
python $S/scaffold.py <slug> --size xhs --fonts source-han-sans,smiley-sans
# 2) 以 index.html 为母版,复制出 4 份变体(只改差异区)
#    src/draft-a.html … draft-d.html ← 共享 <body> 文案,只改 :root tokens / 骨架类 / 主视觉层
# 3) 机检:每稿跑一次(零 token;check_overflow 单次测一个 HTML,4 进程并行跑≈1 次的墙钟)
python $S/check_overflow.py <proj>/src/draft-a.html   # …b/c/d 同理,可并行
# 4) Demo 低分导出(scale 1,小图快出;只 4 稿各自一张)
python $S/export.py --source <proj>/src/draft-a.html --output <proj>/export/demo-a.png --width 1080 --scale 1 --height 1440
#    …b/c/d 同理(可并行跑,互不依赖)
# 5) 拼一张 2×2 联络表(montage;细则见 §5)
python $S/imageops.py montage --in <proj>/export/demo-a.png <proj>/export/demo-b.png \
    <proj>/export/demo-c.png <proj>/export/demo-d.png \
    --grid 2x2 --gap 24 --margin 32 --bg '#e8e8e6' --label --out <proj>/export/demo-sheet.png
# 6) 交付:联络表 + 4 张单图;用户选一个 → 转正(§8)→ 进定点迭代
```

**成本控制三招**:
1. **内容只写一次**——4 稿共享同一份 body 文案,只改 tokens / 骨架类 / 主视觉层;
2. **Demo 只 scale 1**——前期只需「看方向」,选定转正后再 scale 2 出成品;
3. **不重读分册、不跑 4 次看图自检**——机检每稿一次但零 token(可并行),看图自检只看联络表一次(§7)。

## §5 联络表(Contact Sheet)输出

> **本模式的核心体验物**:一张图看全 4 稿。工具 = `imageops.py montage`(C5 网格拼图)。

| 要素 | 规范 |
|---|---|
| 排布 | **2×2**(4 稿);3 稿用 `--grid 1x3`,或 2x2 留空格(工具会 warn 并给建议网格) |
| 间距 | `--gap 24`;外边距 `--margin 32` |
| 标签 | `--label`:每格左上角自动叠 **A/B/C/D** 字母;一句话性格预烧(watermark)或写进消息 |
| 背景 | **中性灰 `#e8e8e6`**(`--bg`),衬托不同底色的稿 |
| 尺寸 | 每稿 scale 1(如 1080×1440 → 成表约 2248×2984,含 gap/margin) |
| 命名 | `export/demo-sheet.png` |

**montage 行为契约**(与 stitch 同族,单行 JSON 输出):格数 > 图数 → 空格留底色(warn 不报错);格数 < 图数 → 报 `GRID_OVERFLOW` 并给建议网格;各图等比缩进格子居中**不裁内容**(联络表要「看全」)。

**兜底**(旧版无 montage 时):`stitch --direction h`(a+b、c+d 各一张)→ `stitch --direction v` 纵拼两行 → `pad` 修比例;字母标签用 `watermark --text A` 逐张预烧。等价但三步,优先 montage。

## §6 选择交互(用户怎么选)

| 用户回复 | Agent 动作 |
|---|---|
| 「选 B」/「第 2 个」 | **转正 B** → 进定点迭代(`pipeline.md` Step 6) |
| 「B 的构图 + C 的配色」 | **混搭**:以 B 为基线,只套 C 的 tokens 区 → 重导 → 确认(改差异区,不是重做) |
| 「都不喜欢,再来 4 个」 | 换一组变体轴再出 4 稿——**允许,但最多一次**,并告知已达轮次预算 |
| 「A 不错,但标题再大点」 | 转正 A → 进 `revision-protocol.md` / `pipeline.md` 改稿协议定点改 |

**纪律**:
1. **选择即转正**——不保留 4 稿并行迭代(否则版本爆炸,改稿纪律失效);
2. **混搭只改差异区**(tokens / 一层结构),不是重做;
3. **再出 4 稿最多一次**——超出应回到追问(`intake.md`)而不是无限抽卡:连续两轮 4 稿都没命中,说明需求本身没说清,多稿救不了。

## §7 成本与 token 治理(必读)

| 项 | 规范 | 理由 |
|---|---|---|
| 触发 | **未触发不出多稿** | 默认单稿(D-10/D-14 拍板):保护 token 与交付节奏 |
| 分册读取 | 本册**读一次**,整轮不重读 | 读取纪律(省 token) |
| 看图自检 | 4 稿**只自检 1 次**——看**联络表**即可 | **铁律 5 写死**:自检仍只在「首版完成 / 用户要求」两时机;AI 视觉贵,联络表已能看方向 |
| 机检 | **每稿跑一次**(4 进程并行,墙钟 ≈1 次);`check_overflow.py` 单次只测一个 HTML,别传目录(目录模式只测 `index.html`) | 零 token、不受铁律 5 限制(每次重导前必跑) |
| 导出 | Demo **scale 1**;仅转正稿 scale 2 | 前期只需方向;4 稿 scale 2 = 4 倍耗时 |
| 内容 | 只写一次,4 稿共享 | 成本不翻 4 倍的关键 |
| 成本目标 | **4 稿总耗时 ≤ 单稿 ×2** | 达标手段:内容共享 + scale 1 + 导出并行 + 机检并行。首次实测(2026-09-21,xhs 1080×1440):单稿 6.6s / 4 稿 8.3s = **1.27×**;若串行导 4 张仅导出环节就 16.9s——并行是达标前提 |

## §8 命名与转正归档规范

```
<slug>/
├── src/
│   ├── index.html            # 转正后的基线(从选中的 draft 提升)
│   ├── draft-a.html … draft-d.html   # 4 变体(选定后移入 _archive/)
│   ├── styles/main.css
│   └── _archive/             # 落选稿(draft-*.html + 对应导出)
└── export/
    ├── demo-a.png … demo-d.png       # scale 1 演示
    ├── demo-sheet.png                # 2×2 联络表
    └── <slug>-2x.png                 # 转正后成品(scale 2)
```

- **转正动作**:选中 `draft-b` → 其内容提升为 `index.html`(或直接以 b 为基线继续),其余移入 `src/_archive/`;
- **不删落选稿**(用户可能回心转意),但**不再参与迭代**——防版本爆炸;
- 版本追加沿用 `pipeline.md`:`-v2` 后缀,不另起命名体系。

## §9 与 intake / Step 1.5 的接线(默认路径不含多稿)

```
(默认)intake 五问 → Step 1.5 设计简报 → 单稿 → …           ← 默认流水线,不含多稿
(触发后)… → 要求/指令/同意提议 → 4 稿 + 联络表 → 用户选择 → 转正 → 定点迭代
```

- 多稿是插在「设计简报之后、动工之前」的**可选分支**;`pipeline.md` 主线文字不变;
- **intake 可选第 6 问**(仅提议一次,不默认问):「要不要一次给 4 个方向供你选?」——答「要」才进本模式;
- 触发后:设计简报**只给一次**(4 稿的共性),简报末尾加一行「本轮出 A/B/C/D 四稿,分别侧重 构图/配色/主视觉/大胆程度」;
- brief 已锁定某维(用户已说「我就要 XX 风格」)→ 该维固定,沿其余轴变化(可 3 稿)。

## §10 多稿自检清单(触发后过一遍,9 条)

1. **确认已触发**(显式要求 / 指令 / 同意提议)了吗?未触发就不该出多稿;
2. 4 稿**内容一致**(同一份文案逐字相同)吗?
3. 每稿差异能**一句话说清**吗?说不清的重想,别硬凑;
4. **标签**(A/B/C/D 字母 + 性格)叠上了吗?
5. 联络表是 **2×2 + 中性灰 `#e8e8e6` 底 + 24px gap + 32px 外边距**吗?
6. Demo 是 **scale 1** 吗?每稿机检都跑过吗(零 token,可并行)?
7. 看图自检**只跑了 1 次**(看联络表),而不是 4 次吗?(铁律 5)
8. 用户选定后,**转正 + 归档**(§8)做了吗?
9. 4 稿总耗时 **≤ 单稿 ×2** 吗?超了先查:是不是重写了内容 / 是不是 scale 2 / 是不是串行导了 4 张。
