## 一、封面尺寸示例与内部决策

### 证据口径

- **腾讯/微信一手资料**：截至检索日期，未找到可公开核验、明确列出上述像素尺寸或裁切规则的官方页面，因此本文不把具体数值称为官方要求。
- **135 编辑文章**：两篇文章给出的是第三方编辑教程和制作示例，页面均注明转载自互联网公开渠道。文章中提到的尺寸、裁切和拼接做法不等于微信平台规则。
- **项目决策**：本节的默认尺寸、版式和视觉规则用于 Artboard 内部制作，不表示平台强制要求。

| 项目 | 资料中的说法 | 来源性质 |

**项目决策映射**：

1. 主封面使用 900×383 作为内部预设，参考两篇 135 文章的常见示例，不标记为平台硬性要求。重点信息放在画面中部是保守的版式选择，不是对后台裁切行为的判断；发布前仍需检查后台预览。
2. 次条默认使用 383×383，便于与 900×383 主图等高拼接，参考 2025 年 135 教程。它不是官方最小尺寸；200×200 和 500×500 也只记录为第三方文章中的示例，不据此推导平台下限或清晰度要求。
3. 合并图采用主图在左、小图在右的拼接流程，参考 135 教程。具体画布尺寸及后台裁切方式以当前账号上传、预览结果为准。
4. 双封面共用同一套主题 tokens、次条元素不超过 3 个，是 Artboard 的内部设计规则。小图文字尽量精简有 2020 年教程作为参考，但不是平台要求。

## 二、内容排版策略(全内联样式路线的依据)

> 本节记录基于第三方工具源码、教程/评测和 Artboard 实现形成的兼容策略，不是腾讯/微信官方规范。编辑器对标签和样式的处理可能变化，发布前应在当前账号的编辑器预览中核对。

| 约束 | 结论 | 依据来源 |
|---|---|---|
| 内联样式 | 第三方评测提到编辑器会剥离部分 `<style>`、`<script>`、class/id；Artboard 将样式内联到元素，减少对外部 CSS 的依赖。具体保留行为以当前编辑器预览为准，不作平台保证。 | doocs/md 第三方方案与 CSDN/腾讯云社区对 doocs/md 的第三方评测 |
| 容器标签 | Artboard 模板用 `<section>` 包裹内容，作为实现选择，不视为平台要求。 | doocs/md 的第三方源码示例、mdnice/135editor 示例 |
| 字号口径 | 正文 15px 基准(代码块 90%,行内代码 87%);行高 1.5–1.75;字间距 0.1em | doocs/md default.css `p { letter-spacing:0.1em }` + base.css `--md-font-size` 体系 |
| 标题手法 | H2 胶囊底色/居中、H3 左竖线、强调色加粗 | doocs/md default.css(h2 background 主色、h3 border-left、strong 主色) |
| 引用样式 | 左边框 + 浅底 + 圆角 | doocs/md default.css `blockquote` |
| 代码块 | 深浅底 + 等宽字体 + 圆角外框;长行换行 | doocs/md `pre.code__pre`(border-radius/overflow)+ 主流编辑器实测 |
| 链接/强调色 | 主色变量驱动,链接无下划线 | doocs/md `--md-primary-color`/`--md-link-color` |
| 中文斜体 | 移动端可读性差 → 主流排版工具弱化斜体(转为着色) | mdnice/doocs 社区实践共识(多篇评测) |

**决策映射**:

1. 零依赖自研解析器(不引 python-markdown/Node)← 部署环境无该依赖,且组件样式表完全自控;
2. 列表不用 `<ul>/<ol>` 而用 section 逐项排 ← 规避编辑器对列表样式的重置(doocs/md 对 li 也做 `display:block` 处理);
3. 分割线用 border-top section ← doocs/md 用 transform scale 实现 0.5px 线,公众号编辑器对 transform 支持不稳,取 border 兜底;
4. 主色 6 套统一主题 ← doocs/md `--md-primary-color` 单主色变量思路的静态化;
   迭代后期收敛到唯一色源 `scripts/_gzh_theme.py`(ink/night/warm/grass/red/mono);
   本文 2026-09 初稿写的"微信蓝 #576b95 为 default"已作废——旧名 `default` 现是 `ink` 的
   弃用别名,主色 `#3b82f6`;
5. `gzh_article.py check` 的白名单是本节兼容性约束的机器化，不表示微信官方认可或保证兼容。

## 三、口径冲突的处理原则

1. **来源分层**：腾讯/微信一手公开文档用于标注平台正式要求；当前后台实测只说明已测试账号、版本和场景下观察到的结果；第三方工具文章只作为制作示例或经验。三类证据不能互相代称。
2. **主封面 900×383（约 2.35:1）**：两篇 135 编辑文章都采用这一示例尺寸。本项目据此设置内部预设，不称为已核实的官方规格。
3. **小图尺寸说法**：200×200、383×383 和 500×500 来自不同年份、用途的第三方教程示例，不能合并成平台尺寸下限或清晰度门槛。本项目默认 383×383，是为了与 900×383 主图等高拼接，不是官方要求。
4. **范围**：本轮只整理公众号图文封面与正文排版，不纳入小绿书等其他内容形态；这是项目范围选择，不是对其他场景平台规范的判断。
