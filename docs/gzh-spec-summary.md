# 微信公众号双封面与排版规范 · 资料归纳

> 本文是 2026-09 迭代(双封面 + 内容排版)的**资料依据与决策记录**:每条实现决策都标注来源。
> 检索时间:2026-09-16。平台官方未公开单一"封面规范页"时,采用多源交叉验证(官方编辑器实测口径 > 主流工具一致值)。

## 一、封面规格(双封面的依据)

| 规格 | 结论 | 依据来源 |
|---|---|---|
| 头条封面比例 | **2.35:1**,推荐 **900×383px** | Canva 尺寸表(900×383)、稿定设计(2.35:1, 900*383, 主信息居中)、壹伴(2026 官方规范仍为 900×383)、华盛科技规格表(头条 900×383)——四源一致 |
| 次条封面 | **1:1**;官方最小 200×200,主流 500×500 或与头条等高的 **383×383** | Canva(小图 200×200)、壹伴/壹伴编辑器(次条 200×200,2025 版 500×500)、135 编辑器(小图 383*383 与大图同高拼接) |
| 转发卡片裁切 | 转发/分享只露**中央 ~383×383**,列表页左图右文裁左侧 → **关键信息居中** | 稿定设计"主要信息展示在图片中间"、material-catalog.md 既有官方口径 |
| 次条设计要点 | 图极小,元素 ≤3,与头条同风格 | material-catalog.md(主流口径) |
| 双封面同稿 | 大图 900×383 与小图 383×383 同高,**可分别制作后拼接** | 135 编辑器"双封面制作…使用图片拼接"、知乎方法专栏(900×383 + 383×383 放一张图上) |

**决策映射**:

1. 主封面 900×383 居中版式 ← 依据"转发只露中央 383×383";
2. 次条默认 383×383 ← 与头条等高便于联动与拼接(200×200 仍满足官方下限,500×500 是 2025 部分工具的新建议,取两者交集的稳妥值,且 383×383@2x=766×766 ≥ 500);
3. 合并图 = 主(左)+ 次条(右)等高拼接 ← 135 编辑器/知乎的"拼接一张图"工作法;
4. 双封面共用同一套主题 tokens ← 次条"与头条同风格"主流口径。

## 二、内容排版约束(全内联样式路线的依据)

| 约束 | 结论 | 依据来源 |
|---|---|---|
| 内联样式存活 | 公众号编辑器剥离 `<style>`/`<script>`/class/id,**只有元素 style 属性内的样式保留** | doocs/md 全站方案(转换器把每条 CSS 规则内联到元素)、CSDN/腾讯云社区对 doocs/md 的评测("代码块转成带内联样式的 HTML,粘贴不丢样式") |
| 容器标签 | 用 `<section>` 包裹内容 | doocs/md base.css(`section` 与 `#output` 双轨)、mdnice/135editor 同口径 |
| 字号口径 | 正文 15px 基准(代码块 90%,行内代码 87%);行高 1.5–1.75;字间距 0.1em | doocs/md default.css `p { letter-spacing:0.1em }` + base.css `--md-font-size` 体系 |
| 标题手法 | H2 胶囊底色/居中、H3 左竖线、强调色加粗 | doocs/md default.css(h2 background 主色、h3 border-left、strong 主色) |
| 引用样式 | 左边框 + 浅底 + 圆角 | doocs/md default.css `blockquote` |
| 代码块 | 深浅底 + 等宽字体 + 圆角外框;长行换行 | doocs/md `pre.code__pre`(border-radius/overflow)+ 主流编辑器实测 |
| 链接/强调色 | 主色变量驱动,链接无下划线 | doocs/md `--md-primary-color`/`--md-link-color` |
| 中文斜体 | 移动端可读性差 → 主流排版工具弱化斜体(转为着色) | mdnice/doocs 社区实践共识(多篇评测) |

**决策映射**:

1. 零依赖自研解析器(不引 python-markdown/Node)← 部署环境无该依赖,且组件样式表完全自控;
2. 列表不用 `<ul>/<ol>` 而用 section 逐项排 ← 规避编辑器对列表样式的重置(doocs/md 对 li 也做 `display:block` 处理);
3. 分割线用 border-top section ← doocs/md 用 transform scale 实现 0.5px 线,公众号编辑器对 transform 支持不稳,取 border 兜底;
4. 主色 4 套主题 ← doocs/md `--md-primary-color` 单主色变量思路的静态化(微信蓝 #576b95 为 default);
5. `gzh_article.py check` 的白名单 = §一硬规则的机器化。

## 三、口径冲突的处理原则

1. **官方编辑器实测口径 > 官方文档 > 主流工具一致值 > 单源说法**;
2. 头条 900×383(2.35:1)是多源一致的"官方口径",直接采纳;
3. 次条存在 200×200(官方最小)/383×383(拼接主流)/500×500(2025 新建议)三说:
   取 **383×383**——同时满足"≥200 下限""≥500@2x 清晰度""与头条等高可拼接"三个约束,冲突消解记录在此;
4. 2025-12 壹伴提到"小绿书新增 16:9/3:4 适配"——属图文消息之外的新场景,本轮不纳入(范围外)。
