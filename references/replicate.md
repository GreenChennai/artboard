# 图片复刻协议(1:1 复刻 / 参考风格)

> 目标:用户丢来一张参考图,产出**布局、配色、字体气质、文案逐字还原**的 HTML 海报,
> 并通过「原图 vs 复刻图」分区比对自检。视觉识别优先级见 materials.md(Agent 视觉优先)。
>
> **核心纪律:每个颜色和度量都必须追溯到测量。**裸眼估的 hex、感觉出来的间距,一律不写进 CSS。
> 色彩靠采样证据,布局靠网格标注——这是复刻不失真的唯一保障(方法论致谢 super-prototyping)。

---

## Step R0 · 备料(参考图落盘 + 缩放比)

- 参考图复制进项目 `ref/reference.png`——**全程别丢**,后面裁切素材、比对都要用原图。
- 算一次缩放比 `K = 目标画布宽 ÷ 参考图宽`:参考图上量到的所有数值 ×K = 写进 CSS 的值。
- 用高度交叉验一次 K(宽高比对不上 → 参考图可能被裁过,先跟用户确认)。

## Step R1 · 读图拆解(先看后量,量必有据)

用自身视觉能力(或 vision_mode=local 时的本地 VQA/OCR)拆解,写成拆解笔记 `ref/notes.md`。

### R1a 网格先行:先命名,再测量

```bash
python scripts/inspect_ref.py grid ref/reference.png -o ref/grid.png --pitch 100
```

- Read 网格图,**先给每个分区命名**(「顶部主标区 / 中部产品区 / 底部条款区…」),
  再用网格坐标描述每区的位置与占比(如"标题区:x 0–1080,y 0–260,占高 18%");
- **没挂上名字的坐标不许进笔记**——盲量出来的数字没有归属,写进 CSS 就是瞎猜;
- 间距/行距/内边距/圆角全部从同一网格标注读出,记参考图坐标,R3 时统一 ×K。
- 小图把 `--pitch` 调小(50);量细部(某按钮的内边距)可对局部再出一张网格图。

### R1b 分区普查:tokens 必须带证据

对每个命名分区单独跑一次普查,按对象类型取对应输出:

```bash
python scripts/inspect_ref.py census ref/reference.png --box x0,y0,x1,y1
```

| 对象 | 看哪个输出 | 原因 |
|---|---|---|
| 底色/卡片/大面积色块 | **flat fills** 首条 | 与四邻全等的像素才是真填充,抗锯齿边不算 |
| 徽章/圆点/logo 底/小色块 | **all pixels** 首条(必要时缩小 box 只留核心) | 太小没有"内部",flat 会是空 |
| 文字颜色 | **ink core**(最暗 5% 均值) | 文字区的众数色是它的背景,不是文字色 |
| 渐变 | flat 为空即信号 | 分区两端各普查一次取两端点 |

1px 分隔线/发丝线:直接取色永远取不到 100% 覆盖(缩放采样下全覆盖不了)。
用 `bbox` 在线所在位置扫一条窄带;若反解出的线色与两侧底色差 ≤2,**这里就没有分隔线,别画蛇添足**。

- **产出:tokens 表写入 `ref/notes.md`,每行 = 色值 + 用途 + 采样位置 + 证据。**
- **没有证据的 token 不许写进 CSS。**

### R1c 字体判定:无把握不点名

- 按字体库两级筛查出 ≤2 候选,渲染对比字形(同一句话、同一字号);
- 前两名难分高下 → 笔记写气质结论(「黑体/特粗/微斜/圆角末端」),选最近似款;
- 交付时注明「字体为近似匹配」,不冒充原字体。

### R1 其余拆解项

1. **画布**:宽高比(量像素比例)→ 匹配尺寸预设(xhs/kv/…)。
2. **版式骨架**:分区数、每区位置占比、网格还是自由布局、视觉动线(Z/C/中轴)。
3. **逐字文案**:所有可见文字**逐字抄录**(OCR 环节;不确定的字标 ▲待确认)。
4. **装饰语言**:贴纸/线框/编号徽章/照片处理方式/噪点纹理…

## Step R2 · 素材:先裁切,后生成(crop, don't generate)

- **参考图里已有的照片/复杂插画 → 直接按测得 bbox 从参考图裁出来**,这才是真 1:1:

```bash
python scripts/inspect_ref.py crop ref/reference.png --box x0,y0,x1,y1 -o img/photo-01.png
```

  登记进 `img/crops.json`(`{"photo-01": [x0,y0,x1,y1]}`,参考图坐标系),重建/换图可复现。
- 例外(才走素材库同主题替换,即风格复刻):①裁切图 <150px 太小会糊;②用户明说要换图/换人;
  ③参考图分辨率太低。intake 时说明选了哪种。
- 参考**图**可以裁,参考**字**不许描:文字必须用真字体排,不做图片字。
- 品牌 logo:占位框 + 备注,不伪造(版权)。
- 裁切素材来自用户参考图:交付时提醒用户确认参考图自身的授权。

## Step R3 · tokens 契约 + 构建

- `scaffold.py` 建项目(尺寸按 R1 匹配的预设)。
- **先写 `:root` 设计 tokens**(R1b 表 ×K 后的值)——它是后续所有分区的对照契约,
  每个色值/圆角/间距都能反查回 notes.md 的一行证据;
- 再写 HTML:分区结构(按 R1a 命名)→ tokens → 字体 → 逐字文案 → 装饰。
- 特效从 effects/title-fx 取配方;参考图有噪声/纸纹等质感别漏。

## Step R4 · 分区数字比对(复刻模式专属)

```bash
python scripts/compare.py ref/reference.png export/o.png -o compare.png            # 整图并排
python scripts/compare.py ref/reference.png export/o.png --region 0,0,1,0.25 -o compare-top.png   # 局部放大
```

- Read 并排图,**逐分区**核对:位置/占比、文案逐字、色值、字体气质、装饰件、动线;
  脚本输出 ΔRGB 均值——哪个区数字大先修哪个,两轮比对的数字变化就是修复进度的证据。
- **差异争议 → 回 R1 重新测量那个分区(拿证据),不是直接对 CSS 打补丁**。
  猜着改 CSS 是在错误答案上叠猜。
- **改了必须重导出再比对——没重导出的修正不算修正。**
- 偏差处理:布局偏差 >5% 或文案有误 → 必修;气质偏差 → 修一轮;细节纹理 → 列为已知差异。
- 比对上限 2 轮(同自检闭环);交付时附 compare.png 给用户自查。

## Step R5 · 归档交付

- 项目内保留三件套:`ref/reference.png`(原图)、`ref/notes.md`(拆解+tokens 证据)、
  `img/crops.json`(裁切登记)——换风格重做(C 模式)时直接复用。
- 交付说明列出:字体近似项、▲待确认文案、已知差异清单、裁切素材清单(提醒确认参考图授权)。

## 忠实度约定

- **默认高保真复刻**(本文档全部规则即为此设计)。
- 用户明说「可以改良/参考风格就行」→ 结构与层级跟随参考,配色字体可按用户品牌替换,
  R1b 普查仍要做(量出原图用色才知道往哪个方向换)。
- 参考图分辨率太低导致文字不可辨:逐字抄录改为「按上下文推断」并在交付时列出推断清单。
