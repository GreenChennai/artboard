# artboard 需求追问(开工前必过,防盲做)

---

## 触发规则

| 输入模式 | 追问强度 |
|---|---|
| A 文案直出 | **Brief Gate 全字段过一遍**(除非用户已给全必需要素,或明说「直接做 / 全按推荐」) |
| B 图片复刻 | 只核 用途 + 尺寸 两字段(视觉基准已在图里;风格配色跟随原图) |
| C 换风格 | 只核 用途 + 尺寸 两字段(风格配色是任务本身) |
| 同会话连做同需求多张 | 检查单只过一次,后续沿用 |

## 开工前检查单(Brief Gate,铁律 8 的落地形态)

> 把"要问什么"从隐性变显性:9 个字段、三态标注、缺项必问。
> **为什么**:用户常忘记给几项,Agent 又被允许"猜着补",结果交付后才发现 → 返工大修。
> 检查单的目的就是把"忘记提"拦在**开工前**。

| # | 字段 | 必需性 | 缺失时的追问话术 |
|---|---|---|---|
| 1 | 用途 / 投放在哪 | **必需** | "这张图发在哪?(小红书 / 公众号 / 电商 / 印刷…)" |
| 2 | 尺寸 / 比例 | **必需** | "尺寸用默认 1080×1440 还是指定?(mm/inch 也行)" |
| 3 | 视觉风格 / 气质 | **必需** | "给我 1–2 个气质词(如 克制 / 热烈 / 编辑感)" |
| 4 | 配色 / 品牌色 | 必需(可由风格推) | "有品牌色 hex 吗?没有我用该风格的默认 tokens" |
| 5 | 素材来源 + 是否需配图 | **必需** | "产品图你有吗?(产品本体只能你提供);另:要不要我找氛围图?" |
| 6 | 必含文案元素 | **必需** | "必须出现的元素有哪些?价格 / 日期 / 二维码 / 账号名 / 副标…逐条给我" |
| 7 | 交付格式 | 可推定 | "默认出 PNG;要不要 PDF / 矢量 / 动图?" |
| 8 | 明确禁忌(反参照) | 可选 | "有没有'不要出现'的?(如不要蓝紫渐变、不要人物)" |
| 9 | 期限 / 优先级 | 可选 | "有 deadline 吗?先要哪一版?" |

### 三态标注

每个字段标成三态之一:

- ✅ **已给**:用户明说了;
- 🟡 **可推定**:由其他字段或上下文推出来,**必须带依据**(写明"依据:你选了 XX"),依据不许是"我觉得";
- ❌ **缺失**:既没给也推不出 → 触发补齐。

### 三态汇报模板(问完即给,一张表看全)

```
【开工前检查单】
✅ 已给     用途=小红书封面 | 尺寸=1080×1440 | 禁忌=不要蓝紫渐变
🟡 可推定   配色=暖纸(依据:你选了"有质感手账风")
❌ 缺失     ① 必含文案元素  ② 是否要配图(初判:建议)
→ 请补这 2 项(其余我按上面的来):
   ① 必须出现的元素有哪些?(价格 / 日期 / 二维码 / 账号名…)
   ② 配图:我去图库找氛围图可以吗?还是纯排版?
```

**硬规则**:

1. ❌ 项**逐条列出并编号**;
2. **一次问完**(不挤牙膏);
3. 用户答复后**重新核一遍**检查单(答复可能引出新缺失);
4. **全部三态齐备(无 ❌)才允许进入 Step 1.5 / Step 4**;
5. 用户答"都行/你定" → 该字段转为"**已给(用户授权默认)**",并在假设清单里列出。

### 「直接做」例外路径

用户明说「直接做 / 全按推荐 / 别问了」→ 跳过补齐,但**必须**输出:

```
【假设清单(请确认)】
用途=小红书封面 | 尺寸=1080×1440 | 风格=暖纸手账 | 配色=暖纸 tokens
素材=图库氛围图 1 张 | 必含元素=主标 + CTA(其余按你的文案) | 交付=PNG
→ 有异议现在说;无异议我按此开工(此后改需求按改稿走,不返工补齐)。
```

**关键差别**:这不是"复述",而是"**请确认**"——把不确定性显式摆到台面,让"忘记提"在开工前暴露。
用户仍不回复 → 按假设开工,并在交付汇报**首行再次列出假设清单**(留痕)。

## 五问(检查单的推荐问法,字段 1–5 的展开)

**Q1 · 用在哪?(决定品类 + 呈现骨架)** — 最重要,必问
- 线上内容(小红书/公众号/朋友圈)→ xhs/square 竖版骨架,Z 动线、首屏即全部
- 电商(主图/横幅/promo)→ square/banner,价格与卖点优先
- 线下印刷(易拉宝/海报/名片/三折页)→ 对应品类,按印刷字号阶与安全边距
- 发布会/品牌 → kv/vertical,深色克制骨架
➡️ 影响的不只是尺寸:骨架(单列/分栏/三段)、字号阶、留白策略全由用途反推。

**Q2 · 尺寸?** — 给默认防遗忘
➡️ 按用途给默认(如"小红书默认 1080×1440,2x 导出")并请确认;有特殊要求直接报 px/mm/inch,agent 换算进尺寸预设。**用户不改就用默认,但不许不问。**

**Q3 · 视觉风格?**
➡️ 从风格清单推荐一个 + 一句话理由;用户描述气质("想要高级感")时由 agent 匹配最近风格并说明。

**Q4 · 配色?**
➡️ 有品牌色给 hex;没有 → 风格默认 tokens 或 style-system 八组色板选一组推荐。

**Q5 · 素材从哪来?(检查单字段 5:素材来源 + 是否需配图)**
➡️ **先判定,再问/再找**:按 materials.md §0 配图判定表给结论(写入 project.json.image_plan):
- 判定"必须"(电商/OOTD/食品)→ 声明"产品本体只能你供图",氛围图我主动去找;
- 判定"建议" → **不问即主动检索** 0–2 张氛围图(默认走图库干净 API;爬虫兜底自动带
  `版权风险-` 前缀并在交付时提醒更换);
- 判定"不需要" → 纯排版(这是**判定结论**,不是默认出口;交付时说明为什么不配图)。
依赖真实拍摄的品类(OOTD/菜品摆盘/探店环境)在 intake 时就声明"需要你供图",不许偷偷拿图库糊弄。
判定表与主动取图纪律的真相源在 materials.md §0;MCP/Bridge 通道见 mcp-assets.md。

**Q5.5 · 有没有明确「不想要」的?(反参照,可选)**
➡️ 一句话即可:"不要蓝紫渐变""不要出现人物""别太促销腔"。反参照直接写进分册禁则优先级最高位,
是消除 AI 默认味成本最低的手段。人格三词(软提示)与反参照一并写入项目 design-prompt.txt,
方法见 design-thinking.md §七。

**Q6 · 要不要一次给 4 个方向供你选?(可选,仅提议)**
➡️ 仅当任务适合多方向探索(风格未定/用户犹豫)且用户未表态时,**提议一次**:
"要不要一次出 A/B/C/D 四稿让你挑?"——**仅提议,用户答"要"才执行**(细则见 multi-draft.md);
答"不用"或未接话 → 单稿。**不默认问、不默认执行**:默认流水线永远单稿,多稿是用户点的那道菜,
主动执行会烧 token 并打乱交付节奏。

## 简报输出(问完即给,生图式)

**前置条件:检查单无 ❌**(或用户已明说「直接做」并确认了假设清单)才进入本步。
五问的答案汇总成一段「设计提示词」输出给用户(画面描述/风格/配色/字体/素材五行),
用户确认或修改后动工——这是与 AI 生图体验对齐的关键一步:**先看到要画什么,再看到画出来的**。
检查单本身写入项目 `design-prompt.txt` 头部,可用 `scripts/check_brief.py` 机检。

## 追问纪律

1. **一次打包问完**检查单要求的全部字段(或触发规则要求的子集),禁止挤牙膏式一问一答。
2. 每项带推荐;用户可整句回「全按推荐」。
3. **缺失 ≥1 → 强制补齐一轮,不许用推荐值静默补齐**:❌ 项逐条编号、一次问完;用户答复后**重核一遍检查单**(答复可能引出新缺失)。
4. 补齐**只一轮**;用户仍不答且未说「直接做」→ 停下来向用户说明"还差哪几项",**不许自行按推荐开工**。仅「直接做/全按推荐」可跳闸,跳闸时必须输出**假设清单并请确认**(见上节模板);用户不回复则按假设开工、交付汇报首行再列假设留痕。
5. 复刻/换风格任务的追问同样复述确认后再动工。
