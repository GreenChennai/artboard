# artboard 改稿决策协议(revision-protocol)

> **何时读**:Step 6 改稿中,用户**说不出要什么但确定不满**——「不够高级」「太乱」「做减法」「差点意思」这类话(必读)。
> 明确指令(「标题换 XX」「红色换蓝」)不需要本册,直接走 `pipeline.md` 改稿协议的 5 行速查。

## 单一真相源声明(防多真相源)

- **本册只讲**:模糊愿望的**诊断**(定到哪一维)、**翻译**(变成什么动作)、**减法**(按什么顺序删)、**提问**(问不出时怎么问)、**反驳**(什么时候不照做)。
- **不重复、不另立**:五维的**验收口径**仍是 `design-review-rubric.md`;各维的**改法规则**仍在各自唯一真相源(`guardrails.md` / `composition.md` / `typography-rules.md` / `style-system.md`);改稿的**流程纪律**(不重跑、机检门禁、轮次上限)仍以 `pipeline.md` Step 6 为准。本册是「从一句模糊话路由到那些既有规则」的协议,不是第二套规则。

---

## 0. 第一原则:愿望是症状,不是指令

**用户的「愿望」是症状,不是指令。** 「不够高级」不是「请加高级效果」,而是「某处让它显得廉价」。
直接照字面加东西(更亮、更多装饰、更多光效)只会更廉价——因为廉价感的来源(满、艳、杂)一件都没去掉。
**翻译 = 找到那个廉价感的来源,然后去掉或修好它。**

由此推出两条工作方式:

1. **先诊断、后动手**:没定位到维度之前不改一个像素(诊断工具见 §1)——猜着改的期望收益为负,每猜错一轮,用户信任掉一档;
2. **定点修改、禁止重生成**:与 `pipeline.md` 改稿协议同一条纪律,模糊愿望不例外——重生成会把用户已认可的部分一起扔掉,等于替用户重新下单。

> **术语**(本册新词,首次定义):**模糊愿望** = 用户对现版本确定不满、却说不出具体改哪里的诉求(本册的处理对象)。**症状词** = 用户嘴里冒出来的形容词(高级 / 简约 / 活力),描述的是感受不是动作。**诊断式改稿** = 先把症状词定位到 rubric 五维中的某一维,再按该维唯一真相源定点修改的改稿方式;与「猜着改」「重生成」对立。

## 1. 诊断坐标系(复用 rubric 五维,不另造第二套)

先问自己:**这句模糊话,最可能砸在哪一维?**

| 症状词 | 大概率维度 | 先看什么 |
|---|---|---|
| 不够高级 / 廉 / 撑不起价格 | D 构图留白 + C 色彩 + E 去 AI 味 | 留白够不够 25% / 饱和度是否过高 / 有无反 AI 味核心项 |
| 不够简约 / 太乱 / 太满 | D 构图留白 + A 层级 | 元素数 / 层级层数 / 留白比例 |
| 做减法 | A 层级 + D 留白 | 强调处数 / 可删元素(直接进 §3 阶梯) |
| 没重点 / 不够抓眼 / 平 | A 层级焦点 | 主标:副标是否 ≥1.5 倍 / 眯眼第一落点是否唯一 |
| 感觉不对 / 差点意思 | B 排版 + D 构图 | 对齐 / 间距节奏 / 比例(九成是间距没吸附基线) |
| 不够专业 | B 排版 + C 色彩 | 主标字体是否有性格 / 网格是否乱 / 装饰是否多 |
| 要更活力 / 太静 | D 构图 | 是否每个板块结构雷同(加动画是懒答案,构图变化才有效) |
| 太土 / 俗 | E 去 AI 味 + C 色彩 | 饱和度 / 字体气质 / 装饰风格 |
| 不喜欢这个颜色 | C 色彩 | 先分辨:是这个**色号**,还是这个颜色在版里的**角色**(用 §4 的问法) |
| 不够亲切 / 太冷 | C 色彩 + 字体气质 | 色温 / 圆角 / 字体性格 |

> 五维即 `design-review-rubric.md` §〇 的 A 层级与焦点 / B 排版质量 / C 色彩与对比 / D 构图与留白 / E 去 AI 味。**诊断坐标系直接复用它,不另造第二套维度**——rubric 已是全库唯一验收源,另造坐标系会让同一处缺陷出现两种说法。

**动作纪律**:诊断到某一维 → 查 `design-review-rubric.md` §三 的映射表找到该维唯一真相源 → 打开那一册按规则改,**不在别处乱补**——哪里都补一点会引入新缺陷,改稿越改越糊。
**禁止**:收到「不够高级」就去 `effects.md` 翻特效往上堆。那是反向操作:高级感缺口在 D / C / E 维(留白 / 饱和 / AI 味),而堆特效在 E 维几乎全是减分项(见 §0)。特效配方只允许 §3 阶梯走到 L5 时为那**一处**主导动作服务。

## 2. 翻译表(症状词 → 真实问题 → 定点动作)

本表是「模糊愿望 → 具体动作」的**唯一真相源**。合格线:每条动作必须落到「改哪个元素 / 哪个 token / 哪个数值」——落不到元素的动作是空话,禁止写进汇报(「调整一下氛围」对用户零信息量)。

| 用户原话 | 真实问题 | artboard 具体动作(定点) |
|---|---|---|
| **「不够高级」** / 撑不起价格 | 缺高端信号:留白小、饱和高、字体杂、装饰多 | ①留白提到 ≥25% 且呼吸位挪到焦点旁(`guardrails.md` 反味 11);②降饱和:收小 accent 面积、提高 muted 比重(直接改风格分册 tokens 的值);③字体收到 ≤2 款、换掉弱字体;④删无功能装饰。**逐步删而不是加**,顺序照 §3 阶梯 |
| **「不够简约 / 太乱」** | 元素与层级双过载 | ①按 §3 阶梯从 L1 执行;②层级砍到 ≤2 层;③强调处数减到 1;④同组卡片合并或删 |
| **「做减法」** | 同上,且用户已授意删 | 直接进 §3 阶梯,从 L1 起。版式 / 装饰层面的删减不必再次征得同意(用户已授权);**删文案内容仍须先确认**——文案是用户资产不是装饰(`guardrails.md` §7 第 5 条) |
| **「没重点 / 抓不住眼」** | 层级缺失,元素等权 | 建立**主导对比**:主标字号提到副标 ≥1.5–2 倍 / 主标独占强调色 / 其余元素降饱和降字号(`composition.md` §二:拉「面积 40 + 对比 25」两项) |
| **「感觉不对 / 差点意思」** | 间距节奏或对齐断裂(**最高发**) | ①全套纵向间距吸附基线单位(`composition.md` §4.2);②主对齐收敛为唯一一种;③组内间距 < 组间距(≥2:1);④同组图片统一宽高比 + `object-fit:cover` |
| **「要更活力」** | 构图单调:每板块同构 | **不要先加动画**——静态导出里动效不存在,治不了静图。①打破重复:连续三块「左文右图」改掉一块;②引入破格元素(一处斜置 / 重叠 / 出血);③拉尺度对比(某元素明显放大)。动图任务才走 `animation.md` |
| **「更专业」** | 弱字体 / 网格乱 / 装饰多 | ①主标换性格款字体、字距收紧;②全部元素吸附栏线(`composition.md` §四);③删装饰;④色彩收到 2–3 色(`style-system.md` §3 收敛为单色系 + 强调) |
| **「太土 / 俗」** | 高饱和 + 俗套装饰 | ①降饱和、按 Itten 面积比调亮暗配比(`guardrails.md` §4);②删「贴纸感」过重的装饰;③换字体气质;④对照 `guardrails.md` 反味 12 条逐条排一遍 |
| **「不喜欢这个颜色」** | 需分辨:色号 or 角色 | **先问一句**(§4 问法):是色号难看,还是角色不对?色号 → 同色系给 2 个备选 token 值;角色 → 问「希望它唤起什么感受」,按 `style-system.md` §3 三公式重新映射 |
| **「不够亲切 / 太冷」** | 缺暖性线索 | 加 **1–2 个**暖性信号即可,不必整版重做:底色色温调暖一档 / 圆角统一加大一档 / 正文换随性字体 / 微文案改口语(改文案须确认) |
| **「规矩点 / 太跳」** | 缺收束 | ①主对齐唯一化;②去掉破格元素(L5 的主导动作做过头也在此列);③层级收回 ≤3 层;④色收敛为单色系 + 一处强调 |
| **「再来点设计感」** | 缺「主导动作」 | 给画面**一个最大胆的决断,只给一处**:一处超大字 / 一处出血 / 一处意外对比(= §3 的 L5)。处处大胆 = 没有大胆,与强调色纪律同理 |
| **「说不出来,反正不像我要的」** | 诊断失败 | 不硬猜。进 §4 引导式提问;仍问不出 → §5 三版方向对比 |

> **判据**:每条动作必须能落到「改哪个元素 / 哪个 token / 哪个数值」;改前想不清落点的,回到 §1 重新诊断,不许带着模糊动作动手。

## 3. 减法阶梯(「更高级 / 更简约 / 做减法」的五级动作)

**减法阶梯**:用户要「更高级 / 更简约 / 做减法」时,按 **L1 删 → L2 减 → L3 挪 → L4 精 → L5 点** 逐级执行的五级动作序列。依据是 `guardrails.md` §2「最高质量的动作通常是删减」:加法人人会做,减法才区分专业与业余——按固定顺序走,是为了防止一上来就加。

**从 L1 逐级执行,每级做完重导看一次,再决定要不要进下一级**(重导前机检照跑,见 §7)。

| 级 | 动作 | artboard 落点 | 做完自查 | 红线 |
|---|---|---|---|---|
| **L1 删**(Delete) | 删**无功能**元素:装饰、多余图标、装饰性英文小字、「差一点」的强调 | 对照 `guardrails.md` 反味 12 条逐条过,该删的删 | 删掉后画面**更好**了吗?没影响就该删(反味 12 原话) | 删到**用户文案内容**必须先确认——那是用户资产,不是装饰 |
| **L2 减**(Reduce) | 减**同类数量与强度**:强调 3→1、层级 4→2、字体 3→2、饱和度降一档 | 逐项数铁律 3 的四组上限(层级 ≤3 / 强调 ≤2 / 特效 ≤3 / 字体 ≤3),超线的砍到线内 | 画面「更安静」了吗?眯眼还有两个以上同强落点吗? | 上限是天花板不是目标:减到线内就停,不为减而减 |
| **L3 挪**(Reposition) | 挪**间距与对齐**:元素吸附栏线 / 三分线 / 基线,呼吸位挪到焦点旁 | `composition.md` §四 网格 + §4.2 基线单位 | 随机抽 5 个元素,都能说出吸附在哪条线?说不出 = 没挪完 | 留白要**有意图**:呼吸位在焦点旁;四边均匀镶边是 D 维 1 分构图(rubric §一 D) |
| **L4 精**(Refine) | 精**细节**:字距 / 行距 / 断行点 / 圆角统一 / 阴影统一 / 数字等宽对齐 | `typography-rules.md` §一~§五 + `numeric-typography.md` + `card-layout.md`;CSS 写法查 `cjk-typography-css.md` | 同级元素完全一致?孤字 / 词中劈开 / 标点行首清零? | 不许用假粗体 / 假斜体 / 拉压汉字凑细节(clreq 三不,`guardrails.md` §3.2) |
| **L5 点**(Delight) | **只加一处「主导动作」**:超大字 / 出血 / 意外对比,给画面记忆点 | 破格构图:`composition.md` §三 骨架 6(满版出血)或 §二 重量对比;一处纵深走 `depth-3d.md`(计入特效计数);主导动作的完整定义与 8 类候选库见 `design-thinking.md` §二(一图只一个);特效配方查 `effects.md`(一图 ≤3 种) | 这处是「故意打破」而非失误?全图只有这一处吗? | 前四级没做完不许进 L5——在满、艳、杂的底子上加点什么都是噪音。**主导动作** = 一张图里唯一一处故意打破规整的决断,其余全部规整 |

> **反模式**:一收到「做减法」就猛删到空。留白要**有意图**(呼吸位在焦点旁),不是四边均匀镶边(`composition.md` §七 自检第 4 条)。
> **顺序不可跳**:L5 只在 L1–L4 完成后允许——记忆点要落在干净的底子上;往噪声里加信号,谁也看不见。

## 4. 引导式提问(诊断不了时)

**不问**「您到底什么意思?」——把组织语言的负担推回给本来就说不清的用户,只会换来第二句模糊话。
**改问**:给 2–3 个**具体选项**让用户挑。「指认」比「描述」容易一个数量级;用户一选,就有起点。

| 用户说 | 这样问 |
|---|---|
| 「让它更抓眼」 | 是**标题**没抓住,还是 **CTA / 二维码**不够突出? |
| 「感觉不对」 | 更像**布局结构**、**间距节奏**,还是**元素之间关系**的问题? |
| 「要更活力」 | 想要**更快 / 更动感**,还是**更丰富**(色 / 元素)? |
| 「不喜欢这个颜色」 | 是**这个色号**难看,还是它在版里承担的**角色**不对? |
| 「不够高级」 | 是**太满**(要留白)、**太艳**(要降饱和),还是**太杂**(要减元素)? |
| 「再调调 / 说不上来」 | 我改三处给你挑:A 间距松一档 / B 主标再大一档 / C 换主色——哪一处对了? |

**Element / Direction / Reference 三问框架**(上表问不出时的通用兜底):
1. **Element(哪里)**:哪一部分不对?(标题 / 图片 / 配色 / 布局)
2. **Direction(哪个方向)**:想要的位移是什么?用**反义词**定位光谱:更大胆 ↔ 更安静 / 更暖 ↔ 更冷 / 更玩心 ↔ 更严肃;
3. **Reference(什么参照)**:「对」长什么样?能给一个例子吗?用户嘴里的「精致」配上参考图,实际常常是「极简 + 大留白」——词与图不等同,以图为准。

> 提问**只问一轮、打包问完**(intake.md 五问的同款纪律)——反复追问会耗尽说不清的用户仅剩的耐心。问完仍说不清 → §5。

## 5. 三版方向对比(完全说不清时的兜底)

**触发条件**:§4 引导提问也问不出——用户只重复「就是感觉不像我想的」。**仅此情形触发**:每次改稿都做三版是滥用,三倍导出成本换不来三倍信息,多数用户其实能从选项里选。

**做法**:
1. 基于现有 HTML,**只改 tokens + 至多一处结构**,做 **2–3 个可对比版本**(`alt-a.html / alt-b.html / alt-c.html`),原版保留;
2. 每版**只差一个维度**(如 A = 更留白、B = 更降饱和、C = 换构图),差异要大到用户**能指认**——只差 5% 的版本没有鉴别力;
3. 三张导出并排给用户,**让用户「指一张」**(比让他描述容易得多);
4. 用户指认后,以那一版为基线回到 §0 继续定点改;落选版本留在项目里不删(用户可能回头再比);
5. **代价控制**:只改 tokens / 一处结构,不重写;总耗时目标 ≤ 单版 1.5 倍。

> **三方向怎么"想"出来**(保守正确 / 激进表达 / 折中巧思,生成期的纸面动作,不加导出成本)见 `design-thinking.md` §六;本节只负责把它们呈现成可对比的版本。

> **与多稿模式的关系(防双轨)**:本节是**改稿阶段**的兜底呈现;完整模式见 `multi-draft.md`(备选模式:默认单稿,仅用户要求 / 说指令 / 同意提议时触发——一次 4 稿 + 一张 2×2 联络表 + 选择即转正)。两者**互指、不双轨**:开工前出多稿走 multi-draft,**改稿中途选方向仍走本节**(改稿不重跑,不为选方向回炉 4 稿);本节同时是「要不要升级用多稿」的提议入口(§4 问不出时提议一次,用户同意才出——提议 ≠ 执行)。

## 6. 何时该「反驳」而非执行

先把「模糊愿望」与「具体功能请求」分开:前者按 §0 翻译;后者多数照办——但**功能型请求常让图变差**(「标题加发光描边 + 渐变 + 阴影三件套」是最常见的一类,配方越全越像促销传单)。

**反驳公式**:**替代方案 + 理由 + 要不要看效果**。不说不,给路。

> 例:「这三层效果会把标题带成『商品促销感』,和您要的『高级』正好相反。我用『一处细描边 + 大留白』能达到同样的醒目度——要不要做出来对比一下?」

**必须反驳的三类信号**(仅限这三类,其余请求照办——超出三类的反驳是抬杠):
1. **违反铁律 3 上限**(特效 / 强调 / 字体 / 层级超限)——上限是全库验收口径,破一次全库数字打架;
2. **撞反 AI 味核心项**(紫蓝渐变 / AI 高发字体当主标 / 均质卡片墙,`guardrails.md` §5)——「不像 AI 生成」是最高优先级审美约束;
3. **毁可读性**(正文对比度掉到 4.5:1 以下、文字压图无垫层)——好看但读不了等于没做。

反驳时**引用对应分册条文当理由**,不说「我觉得」。用户听完仍坚持 → 照做,留版本,交付汇报里记一句已知风险。

## 7. 改稿执行纪律(承接 pipeline.md,不另立流程)

1. **定点修改**:只动诊断到的部位,**禁止从头重生成**(除非用户明说「重新来一版」)——重生成扔掉用户已认可的部分,等于替用户重新下单;
2. **重跑机检**:每次重导前跑 `scripts/check_overflow.py`——改文案 / 字号 / 间距正是溢出最高发的三件事;机检零 token、不受自检两时机限制(`pipeline.md` Step 6.0);
3. **留版本**:旧版存 `index_v2.html` 或 `alt-*.html`,不覆盖——改稿方向未必一次选对,回退路径就是版本;
4. **不自动自检**:改稿阶段不重跑 rubric 五维打分(铁律 5;打分是验收动作,只在首版完成 / 用户要求两个时机)。§1 的「诊断」是动手前的定位动作,不是打分——两者别混,诊断不产分数;
5. **汇报改动点**:说清「改了哪一维、动了什么、预期效果」——**不解释设计原理**(用户要结果不要上课;但「哪一维」要报,训练用户下次会描述)。

## 8. 「高级感」正向清单(进攻,与反 AI 味防守清单分立)

`guardrails.md` 反 AI 味 12 条是**防守**——「别像 AI」;本清单是**进攻**——「像专业设计」。**两份清单不合并**:防守项全过只说明不丑,高级感来自下面这些**主动做出来**的特征。用法:反味 12 条先全过(否则是负分起点),再逐条对照本清单补齐。

| # | 高级感信号 | 判据(可观察) | 维度 |
|---|---|---|---|
| 1 | 克制的配色 | 低饱和底 + 一点高饱和;accent 面积 ≤10%(60/30/10) | C |
| 2 | 慷慨的留白 | 留白 ≥25%,呼吸位在焦点旁 | D |
| 3 | 字体少而精 | ≤2 款,字距有意图,无弱字体 | B |
| 4 | 对齐纪律 | 全图一种主对齐,每个元素说得出归属 | D |
| 5 | 尺度的自信 | 主标顶到字号阶上限(1080 宽 88–160px),小字敢小,中间地带少 | A |
| 6 | 一处主导动作 | 有且仅有一处「故意打破」,其余规整(定义见 §3 L5) | E |
| 7 | 材质克制 | 每处阴影 / 圆角 / 渐变说得出理由 | E |
| 8 | 细节到位 | 无孤字 / 词中劈开 / 标点行首;数字 `tabular-nums`;对比度达标 | B |
| 9 | 信息诚实 | 不编数据、不堆装饰性英文小字 | E |
| 10 | 色彩有面积比 | 亮色小面积、暗色大面积(Itten,`guardrails.md` §4) | C |

**一句话公式:高级 = 少的东西 + 做到位 + 一处意外。**

> **与 rubric 的关系**:本清单是「往 5 分改」的方向感;`design-review-rubric.md` §一 各档才是判分口径。自评仍引用 rubric 原文,本表不产生第二个分数。
