# ADR 0012:视频场景卡模式(五段式时间轴)与录制偏移对策

日期:2026-09-13 · 状态:已采纳(v1.6.0,cutflow 视频桥实测反馈驱动)

## 背景

cutflow(视频总控技能)经 `rs_artboard` 桥把 artboard 卡片插进视频时间轨,
口播→动画卡→口播交替。实测三大问题:

1. **入场动画被吃掉**:WPI 的 GIF/MP4 录制从「页面加载完成后的稳定点」开始
   (wait_assets + scroll_reveals 之后),比 CSS 时间轴 0s 晚——1080×1920
   全本地资产实测 **1.7–1.9s**(时钟探针法,animation.md §八);从 0s 起播的
   入场动画在成片里残缺甚至整体缺失(animation.md §六旧实测:
   "入场 1.2s 的案例,148 帧里全是循环态")。
2. **没有出场**:旧规范只有循环/入场概念,"终态必须仍是合格静态海报"
   把内容钉死在画面上——卡片切回口播时内容瞬间消失,切换僵硬。
3. **不生动**:旧规范只允许 transform/opacity,缺科普/教程类的信息演进手段。

另:`infinite` 动画会让 WPI early_stop(有限动画结束+画面稳定即停)
永远不触发,录满 `--max-wait`(默认 15s)。

## 决策

1. **动效分册分双模式**(animation.md §〇):模式 P 海报循环(原规范不变)、
   模式 S 视频场景卡(新)。判定问题:"产物是独立循环看,还是接在口播后面播?"
2. **模式 S = 五段式一次性时间轴**:前置静置(≥2.0s,空卡;实测覆盖录制
   起点 1.7–1.9s)→ 入场(0.5–0.8s,decelerate)→ 持住(与口播句对齐,
   可含信息演进)→ 出场(0.4–0.6s,accelerate,方向延续、stagger 反序)→
   收尾静置(≥0.3s)。
3. **录制偏移的对策选"页面侧静置补偿"**:入场 delay 统一 ≥2.0s,让偏移吃在
   静置段上——片头"空卡一拍"是正常剪辑呼吸,±0.3s 的变化不可感;
   导出片长 ≈ 时间轴总长 − 1.8s ± 0.3s,cutflow 按探测时长挂轨。
   新机/新画幅用时钟探针法实测校准(animation.md §八)。
   "resize 重对表"方案已实测否决:录制期间主线程重绘/样式提交被采样节奏
   饿死,事件结果与 `currentTime` seek 均不上屏(合成器动画照跑、
   `evaluate` 能通)——根治需 WPI 提供录制起点钩子(上游建议)。
4. **模式 S 全 finite**:禁 `infinite`;环境微动用有限次数并算入总时长。
5. **可动属性白名单分级扩容**(L1 transform/opacity → L2 clip-path、
   stroke-dashoffset、@property → L3 filter):L2/L3 是 paint-only/restricted
   使用,配数量与尺寸护栏;重排属性依旧全禁。
6. **静态版另出**:场景卡直接导 PNG 会得到空卡(终态=退场后);需要静态图时
   复制为 index_static.html 删掉出场动画再导。

## 为什么不是别的

- **改 WPI 加"录制起点钩子"**(如录制前调用 `window.__wpiStart()`/重放
  时间轴):一劳永逸且无静置浪费,但 WPI 是独立仓库——按"改动最小、契约
  在消费侧"取舍,先用静置补偿;若未来做口型级精确对齐,再上 WPI 钩子
  (届时只删 --t0)。**注意**:页面侧监听 resize/scroll 自行重对表的方案
  已实测否决(见决策 3 与实测节)——不要重试。
- **录制偏移用负 animation-delay 抵消**:偏移量非确定性,负延迟会把
  入场中段当首帧,比静置段更糟。
- **出场用循环动画的相位回绕实现**:相位不可控(见 §六旧实测),且与
  early_stop 冲突。
- **语义断行交给浏览器**(`word-break: auto-phrase`):Chrome 119+ 且
  仅日/韩词典,中文无解——断点必须作者手动给(typography-rules.md
  §一「标题语义断行」,依据 CSS Text 3 keep-all + `<wbr>` 官方用法)。

## 影响

- cutflow 桥侧规则(rules/artboard.md "动图约束:2–6s 无缝循环")应同步
  认可模式 S 卡——cutflow 仓库另行修订;本仓库先保证契约自洽。
- 旧案例(海报循环)零改动;模式 S 是纯增量,SKILL.md 铁律 6 已分叉表述。

## 实测(2026-09-13,1080×1920,fps 25,--max-wait 7-9,ffprobe 时长反推)

- 无重对表:录制起点 1.70–1.85s(四次导出反推,紧;时钟探针首帧读数
  1.70/1.73s 互证);实际采样 ≈20fps(WPI 自适应;播放速度=真实时间)。
- **"resize/scroll 重对表"否决实测**:监听事件把动画 `currentTime` 归零,
  三轮导出全部无效——录制期间主线程重绘与样式提交被采样节奏饿死:
  文本探针冻结在初值、事件日志不上屏,但合成器动画照跑、`evaluate`
  能通。教训:**录制环境里"JS 执行了"≠"画面会变"**,探测必须用
  合成器可见的信号(transform/opacity 状态)或 ffprobe 时长反推。
- **同元素双动画事故(已立硬规则)**:入场/出场挂同一元素——无论简写相叠
  (后者覆盖前者的 animation-name)还是逗号列表(后一场的 backwards fill
  在同属性上压住前一场:出场 from opacity:1 盖住入场 from opacity:0)——
  效果都是**元素从 0s 起全程可见**,即"没有入场、画面常驻";极易误诊为
  录制偏移,抽帧+裸浏览器 opacity 探针才定位。正解=**嵌套双层(外入内出)**,
  裸 Playwright 三态验证(1.7s 隐/2.5s 入场中/6.3s 已退)+ 终验导出:
  帧 0 空卡、0.4s stagger 入场中、4.5s 反序出场中,全链路上片。
- 微动跨越出场结束点:内容退场后 orbit 独自在空卡上漂
  → 新增"微动结束 ≤ 出场结束"硬规则。
- 终验(前置静置 2.0s + 逗号列表):入场 stagger 完整在片、出场 stagger
  完整在片、首尾空卡干净。
