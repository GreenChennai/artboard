# 品类规范 · 微信公众号双封面(gzh-cover)

> **主题统一源(11 迭代)**:封面主题不再本地定义,来自 `scripts/_gzh_theme.py`
> (ink/night/warm/grass/red/mono 6 套 × 全量角色)。旧名 `blue→ink` / `dark→night` /
> `green→grass` 仍可用但打印弃用提示;**green 色值已统一,与旧版不同**。图文侧同源,改色一次两产物同变。

> 品类分册:视觉风格可从风格清单选,或直接用 `scripts/gzh_cover.py` 内置主题。
> 品类规范只管尺寸、安全区、版式族选择与导出纪律。规格来源与证据链见 `docs/gzh-spec-summary.md`。

> **本册分工(14 迭代起)**:本册 = **规格 + 工作流 + 判据**;
> **版式族详表**(6 族逐族的 px 坐标、装饰清单、案例)→ [`../gzh-cover-layouts.md`](../gzh-cover-layouts.md)。
> 要"照着排就能出图",**必须两册一起读**:本节定"用哪族、什么时候用",详表定"怎么摆"。

## 一、画布与导出

| 产物 | CSS 画布(px) | 比例 | 默认导出(scale 2) | 用途 |
|---|---|---|---|---|
| 头条主封面 | 900×383 | 约 2.35:1 | 1800×766 | Artboard 内部预设，参考第三方教程；不代表微信官方规格 |
| 次条副封面 | 383×383 | 1:1 | 766×766 | Artboard 内部预设，参考第三方教程；不是官方下限 |
| 合并预览图 | 2680×766(scale 1 直出) | — | 2680×766 | 双封面单图对比/存档/汇报 |

- 一键工作流:
  ```bash
  python $S/gzh_cover.py new <slug> --title "标题" --theme ink --layout center-band # 显式选择新版居中色带
  python $S/gzh_cover.py new <slug> --title "紧急招人" --layout giant-caps --theme ink
  python $S/gzh_cover.py new --list-layouts                                       # 看 6 族适用文案形态
  python $S/gzh_cover.py export <slug>            # 默认三图齐出(合一导出)
  python $S/gzh_cover.py export <slug> --only main   # 只导主封面
  python $S/gzh_cover.py export <slug> --only sub    # 只导次条
  python $S/gzh_cover.py merge <slug> --gap 57       # 只重拼合并图(不重导)
  ```
- 静态检查:`python $S/gzh_cover.py check <slug>`。六个新族做完整几何/安全区检查；无 `--layout` 的 legacy 旧模板会返回 `coverage=partial` 并标出跳过项,不要把“未测量”当通过。
- 产物命名:`cover-main-<slug>.png` / `cover-sub-<slug>.png` / `cover-merged-<slug>.png`,
  文件名自带用途,可直接在公众号后台上传。
- 导出主路径与全技能一致(**Kiln 原生引擎** → `scripts/export.py`);合并图是纯像素拼接(`kiln-cli img stitch`),**不重新渲染 HTML**,单张内容零形变、零重采样。

## 二、保守安全区(Artboard 内部排版约定)

截至本轮检索，未找到腾讯/微信一手公开资料确认转发卡片固定显示中央 **383×383**，或列表页从左侧裁切。中央约 383×383 区域是 Artboard 的保守排版安全区，不是平台裁切保证；上传后应检查当前账号和展示场景的后台预览。

```
 0                    258                            642                   900
 ├──── 左侧外围约 258 ────┤   中央保守安全区约 383   ├── 右侧外围约 258 ──┤
 │  装饰/非关键信息      │◄── 关键信息优先放这里 ──►│  装饰/非关键信息    │
```

| 区 | x 范围(约) | 建议放置 | 内部排版约定 |
|---|---|---|---|
| **保守安全区** | 258–642 | 眉题/主标/副题/副题胶囊 | 关键信息优先放入；避免长句、二维码和需指读的图表 |
| **左侧外围** | 0–258 | 色带、水印、竖排标签、页码、贴纸等装饰 | 避免放必须完整阅读的信息 |
| **右侧外围** | 642–900 | 水印、徽标、底纹、贴纸、图片等非关键信息 | 避免放必须完整阅读的信息 |

上述区域划分只用于 Artboard 版式设计。外围内容是否被裁切取决于平台展示场景，不据此推断裁切行为；装饰或图片出血可延伸到外围，但不应承载关键信息。18 张参考里 6 张版(1/2/3/4/6/8)把主标放到左右两侧，本册吸收其手法时，将主标坐标压回内部安全区。

## 三、版式族(6 族;选择 → 摆放分两步)

### 3.1 族一览(细节见 [`layouts`](../gzh-cover-layouts.md))

| slug | 中文名 | 语气 | 层 | 信息形态(何时选) |
|---|---|---|---|---|
| `center-band` | 居中色带 | Quiet | 2–3 | 通知/通稿/喜报/每日资讯;**默认**,少文案也稳 |
| `band-editorial` | 左文带 | Power/Editorial | 3–4 | 标题 7–14 字较合适、需要两行断行且有副题 |
| `stack-cards` | 分层堆叠 | Playful | 3 | 活动/招募,要"卡片 + 贴纸"的点击感 |
| `giant-caps` | 巨字压边 | Power | 1–2 | 短标题优先,**字即画布**(倡议书/重要通知/90 周年) |
| `kraft-note` | 牛皮便签 | Playful/Quiet | 3 | 手作感:市集/茶歇/迎新/开业,配手写体 |
| `plate-page` | 画页分栏 | Editorial | 5–6 | 本地照片/插画必填;时间、地点、主办等 metadata 可选 |

### 3.2 三步选族(建议优先级)

1. **先看信息件。** 需要照片/插画时选 `plate-page` 并提供本地图片;时间、地点、主办等 metadata 可按需填写。标题 + 副题可选 `center-band` / `band-editorial`;后者需要主封副题。
2. **再看标题长度。** 1–6 字可优先尝试 `giant-caps`;7–14 字较适合 `band-editorial`(须有副题)。15–20 字仍可尝试适配版式,以 `gzh_cover.py check` 的实际字宽/断行结果为准;超过 20 个可见字符会被拒绝。若需要缩短标题,先征得用户确认。
3. **最后看气质。** 要热闹 → `stack-cards`;要人味 → `kraft-note`;说不清就选 `center-band`。这些长度是排版建议,不是微信平台规格。

### 3.3 每族一句"什么时候绝对不要用"

- `center-band`:标题 ≤5 字(空)/ 要贴纸感。
- `band-editorial`:无副题 / 无任何图且右半空落。
- `stack-cards`:三层形状语言不统一 / 已要纸感(别和 `kraft-note` 叠)。
- `giant-caps`:标题 >8 字 / 有地点日期要塞。
- `kraft-note`:深底主题 / 标题 ≥10 字 / 只有一张贴纸撑场。
- `plate-page`:**零图片素材**。

## 四、字号阶(900 宽主封面基准)

### 4.1 分元素

| 元素 | 字号 | 说明 |
|---|---|---|
| 主标(`center-band`/`band-editorial`) | 44–64px | 一行 ≤12 字;次条 ×0.62 |
| 主标(`giant-caps`) | 96–150px | 只给 ≤6 字;行高 0.92(展示字豁免,见 `typographic-expression.md §八` #5) |
| 眉题 | 14–18px | 拉开字距 0.42em,品牌色 |
| 副题 | 16–20px | 弱化色,一行 ≤16 字 |
| 副题胶囊 | 16–18px | 胶囊内文字 ≤10 字,一图 ≤1 个 |
| 英文水印 | = 主标字号 或更大 | 透明度 ≤10%,**不承担信息** |
| 期号/页脚 | 14–15px | 装饰层,透明度 ≤35%,只进外围装饰区 |
| 次条主标 | 主标 × 0.62 | 383/618 的版面等价;次条副题 15–16px,眉题 12–13px |

### 4.2 标题长度与字号建议(最终以实际字宽和版式检查为准)

| 字数 | 建议字号 | 行数 | 可用族 |
|---|---|---|---|
| 1–4 | 96–150 | 1 | `giant-caps` |
| 5–6 | 64–96 | 1–2 | `giant-caps` / `stack-cards` |
| 7–9 | 52–64 | 1–2 | `center-band` / `band-editorial` |
| 10–14 | 44–52 | 2 | `band-editorial` |
| 15–20 | 40–44 | 2–3 | `center-band` / `band-editorial`; `plate-page` 仅在需配图时考虑 |
| >20 | — | — | 超过程序硬上限会被拒绝;若需精简文案,先征得用户确认 |

- 两行时用 `--title "上句\\n下句"` 显式断行,**断点选语义边界**;
- 折行后每行字数差 ≤3,末行 ≥3 字(禁孤字);
- 字号用**固定 px**,不用 vw/vh(导出语境视口 ≠ 画布,铁律 1)。

### 4.3 断行与字号由代码算,不把坏断点交给 CSS(2026-10 迭代)

> 起因:主标「双封面时代的公众号排版指南」曾被 CSS 折成 `…排版指 / 南`——**孤字独占一行**；
> 安装版实拍又把「城市更新的三条路」断成「城市更 / 新的三条路」，字数看似均匀、语义却断裂。
> 这正是"每次都要手动调很多次"的来源之一。

**现在 `_gzh_layouts.py` 负责推荐断点，`gzh_cover.py check` 再把坏断点变成可见失败：**

1. `break_lines(text, max_lines, max_chars)` 穷举可行断点：行数优先少、限制孤字与行宽，并对
   高置信**复合词组**(如「城市更新」「双封面」「公众号」「排版指南」)内部断开加重惩罚；
   保留英文词间空格；用户显式输入的换行及 `<br>`/`<br/>`/`<br />` 是硬边界，不被算法吞掉。
   它不是完整中文分词器，不会臆称理解所有词义。
2. `gzh_cover.py check` 的 `title-word-break` / `title-particle-edge` 检查显式断点是否拆开词组、
   或把助词推到行首/行尾；`title-min-px` 和 `title-width-fit` 同时检查主封与次条的字号下限及实际安全栏宽。
   若没有自然断点，先改写标题或换布局，再渲染复核；不要把自动 CSS 折行当作排版验收通过。
   `check` 仍是结构/断点证据，不代替实图审美判断。
3. `title_px() / sub_px()` 按**实际字宽**反推字号(中文 1em、ASCII 0.55em、空格约0.32em、再叠字距)，
   而不是按字数分三档。只按字数分档时"周末手作市集"8 字×54px=432px > 安全区 383px，必然回退折行。

内容修辞优先：遇到「城市更新的三条路」，可改成「城市更新：三条实践路径」，让结构本身给出自然断点，
而不是硬把「更新」拆开。

**各族单行上限(超过就进断行):**

| 族 | 主封面 | 次条 | 备注 |
|---|---|---|---|
| `center-band` | 383 宽 / 1 行 | 6 字/行 | 次条 413 宽,一行 6 字最稳 |
| `band-editorial` | 6 字/行(文字栏 348) | 5 字/行 | 左文带天然适合两行 |
| `stack-cards` | 5 字/行(卡内 331) | 4 字/行 | 卡内留白大,超 5 字换族 |
| `giant-caps` | ≤5 字(超了按 300 宽反推字号) | 4 字/行 | 该族本职是 1–4 字 |
| `kraft-note` | 6 字/行,**字号 ×1.06 修正** | 5 字/行 | 标题带 -1.2° 倾斜,外接盒更宽 |
| `plate-page` | 5 字/行(板面 300) | 4 字/行 | 次条还压 3 行 meta,标题必须收窄 |

> `kraft-note` 的 ×1.06 是实测出来的:倾斜 -1.2° 后 60px×8 字的外接盒 > 348px,
> 末字「集」被裁成孤字。凡是给标题加 `transform: rotate()` 的族,字号都要按外接盒重算。

## 五、双封面联动规则(工作法核心)

1. **同一套 tokens**:主/次条共用同一主题色板(唯一色源 `scripts/_gzh_theme.py`,6 套:
   ink/night/warm/grass/red/mono;旧名 blue/dark/green 是弃用别名),字体同款——信息流里两张图要像"同一个栏目"。
2. **中央保守安全区约 383×383**:这是 Artboard 的内部版式选择，不代表转发卡片或列表页的固定裁切规则。主标/眉题/副题优先排在该区域；实际展示以当前公众号后台预览为准。
3. **次条元素 ≤3**:小图(列表里只有 ~78px 见方)只放"色块标记 + 眉题 + 标题(+副题)"。
4. **标题一行原则**:主标 ≤12 字一行;两行时用 `\n` 显式断行(断点选语义边界)。
5. **期号/页脚是装饰**:允许落在安全区外,但不得压到中央信息。
6. **次条 = 主封面的"缩排"**(14 迭代新增):保留底色 / 字体 / 标题承载方式 / 标记形状;
   **删除**竖排标签、英文水印、双行错位、期号章、胶囊;**缩小**主标 ×0.62。
   默认 `--sub-mode same`(同版缩排);`--sub-mode minimal` 时次条退到"色块 + 标题 + 一行小字"。
7. **`--sub-mode flat`**:次条全反色/纯色底,仅用于主封面本身极简、需要次条更强的场合——**一稿里只能用一次**。

## 六、合并图规范

- 版式:主封面(左)+ 间隔 57px×scale + 次条(右),等高拼接,浅灰底 `#f6f7f9`。
- 间隔可用 `--gap` 调整;底色可用 `--bg` 换(传品牌色时注意与封面底色的区分度)。
- 纪律:合并图是**预览/汇报交付物**,公众号后台上传仍用单张原始文件(比例各自正确)。

## 七、调性禁则

1. Artboard 内部要求关键信息优先置于中央约 383×383 保守安全区。
2. Artboard 内部要求左右外围只放装饰或非关键信息，不把外围内容视为平台必然会裁掉的区域。
3. 主/次条禁用不同字体/不同主色(联动感第一)。
4. 次条禁超过 3 组元素;禁长句(>10 字/行)。
5. 合并图禁拉伸凑比例——宁可改 gap,不可变形。
6. **禁 emoji 当装饰符号**(参考图里的相机/排球是插画,不是 emoji)。
7. **禁炫光/发光字压主标**;禁"蓝紫渐变 + 发光"(`guardrails.md §4`)。
8. **贴纸 ≤2 枚、旋转 ±6°(次条 ±3°)合一**;禁在安全区边缘放"半遮半掩"的装饰。
9. **色相 ≤2、强调 ≤2 处、字体 ≤3 款、特效 ≤3 种**(`guardrails.md` 铁律 3 的封面化)。
10. **禁把标题箱 + 描边字 + 贴纸**三件同时叠在一个族里(= 三个焦点)。

## 八、产出"不素"的最低配置(交付前数一遍)

素版的问题不是不美,是**元素只有 3 件**。一张合格的封面至少:

| 层 | 至少 | 最多 |
|---|---|---|
| 信息件(眉题 / 主标 / 副题) | 2 | 3 |
| 标题承载物(色块 / 白卡 / 带 / 便签 / 描边) | **1** | 1 |
| 底纹或水印(点阵 / 斜纹 / 颗粒 / 弧光 / 巨字) | **1** | 2 |
| 边缘物(贴纸 / 徽标 / 竖排标签 / 页码) | 0 | 2 |
| **合计** | **5** | **8** |

> 数不满 5 件的,不是"极简",是**没做完**;超过 8 件的,先删"最不像人放的"那件。

## 九、异常与降级

| 报错 | 原因 | 处理 |
|---|---|---|
| `KILN_NOT_FOUND` | 渲染引擎未部署 | 跑 `scripts/setup_kiln.py`,或设 `ARTBOARD_KILN_CLI` |
| `NO_FONTS` | 所选字体目录不存在 | 换 `fonts/` 下已有目录,或用默认 `auto` |
| `BAD_LAYOUT` | `--layout` 不是 6 族之一 | `new --list-layouts` 查看 |
| `MISSING_EXPORTS` | 合并前单张未导出 | 先 `export --only main` / `--only sub` |
| `STITCH_FAILED` | 合并图拼接失败(`kiln-cli img stitch`) | 检查两张单张 PNG 是否存在且未损坏 |
| `EXISTS` | 项目已存在 | 换 slug 或 `--force` |

## 十、交付前自检(8 条,与详表 §十四 呼应)

1. 三件关键信息是否优先放在 x 258–642 的保守安全区内?
2. 左右外围是否只放装饰或非关键信息?
3. 标题字数落在 §4.2 映射区间?
4. 元素 5–8 件(§八)?
5. 次条 ≤3 件且同底色/同字体/同标题承载?
6. 缩到 15% 宽,主标仍可辨(缩略图测试)?
7. 有没有装饰性英文小字(反味自检第 8 条)与发光字?
8. 能一句话说出"为什么选这族"?
