# artboard 设计评审打分表(rubric)

> **何时读**:Step 6 自检的两个时机 —— ①首版 HTML 完成;②用户明确要求检查。
> 给 `guardrails.md` 的通过式清单加**分值与权重**,让「要不要返工」可计算。
> 铁律 5:改稿阶段**不打分**,定点修改重导即可。

---

## 〇、五维度 × 0–5 分

| 维度 | 权重 | 它回答的问题 |
|---|---|---|
| **A 层级与焦点** | 30% | 眯眼第一落点唯一吗?层级拉开了吗? |
| **B 排版质量** | 25% | 中文断行、行宽、中西文间距、数字对齐到位吗? |
| **C 色彩与对比** | 20% | 对比度达标吗?强调克制吗?色盲能分辨吗? |
| **D 构图与留白** | 15% | 有骨架吗?留白有意图吗?元素都有归属吗? |
| **E 去 AI 味** | 10% | 截到社交平台会不会被说"一眼 AI"? |

加权总分 = `0.30×A + 0.25×B + 0.20×C + 0.15×D + 0.10×E`

---

## 一、逐档判定标准

> 每档给**可观察的事实**,不给形容词。打分时引用画面上的具体位置,不许凭感觉。

### A · 层级与焦点(30%)

| 分 | 标准 |
|---|---|
| **5** | 眯眼第一落点唯一;主标:副标 ≥1.5 倍字号差;层级恰好 3 层且每层职责清晰;强调 ≤2 处且都给了最该看的东西 |
| **4** | 落点唯一,但层级差在 1.3–1.5 之间(临界) |
| **3** | 有两个同等强度落点,但其中一个可通过降对比/缩小在 5 分钟内修好 |
| **2** | 层级 ≥4 层,或强调色 ≥3 处 |
| **1** | 层级差 <1.2 倍("差不多大"阵列),或主标被装饰压过 |
| **0** | 没有焦点——所有元素等权重 |

**硬伤(直接计 0,不看其它)**:主标被图片/装饰盖住不可读。

> A 维打分时把**缩略图可读性**并入「第一落点唯一」一起判:缩到 15% 宽主信息(主标+关键数字)仍可辨才是 5 分;判据与修复方向见 `composition.md §二`「缩略图可读性」。

### B · 排版质量(25%)

| 分 | 标准 |
|---|---|
| **5** | 无孤字、无词中劈开、无标点行首;行宽 25–40 字;中西文间距 ≤1/4 em;数字列 `tabular-nums` 对齐;**文字无一处越出容器边框**(`check_overflow.py` 报 `ok:true`) |
| **4** | 一处可容忍瑕疵(如某行 42 字,超 2 字;或越界仅 4–8px 且不可见) |
| **3** | 存在孤字或一处词中劈开,但不在主标;或有 1 处 8–20px 的文字越框 |
| **2** | 主标有词中劈开,或行宽 >50 字,或 ≥2 处文字越出卡片框 |
| **1** | 文字明显越出卡片框(≥20px),或正文用了假粗体/假斜体 |
| **0** | 字体没加载(系统回退),或文字被裁切/出画布 |

**硬伤(直接计 0)**:字体回退;文字溢出画布;文字越出卡片框 ≥20px(可见的"字跑到色块外面")。

> **为什么单列这一项**:所有人工自检都以**画布**为溢出参照系,「文字出卡片但仍在画布内」
> 会被五维全部放过。判据从 `check_overflow.py` 的几何量测取(见 `card-layout.md §七`),
> 不靠肉眼——线条颜色相近时肉眼无感。

### C · 色彩与对比(20%)

| 分 | 标准 |
|---|---|
| **5** | 正文对比度 ≥4.5:1、大字 ≥3:1(`color-contrast.md` 定义);强调 ≤2 处;色盲三型模拟下主信息仍可辨 |
| **4** | 对比度达标,但强调 3 处 |
| **3** | 一处对比度在 3:1–4.5:1 之间(正文不达标) |
| **2** | 强调 ≥4 处,或压图文字无垫层 |
| **1** | 正文对比度 <3:1 |
| **0** | 纯黑字压纯白底(刺眼)或文字与底同色系不可辨 |

**硬伤(直接计 0)**:文字与背景对比度 <2:1。

### D · 构图与留白(15%)

| 分 | 标准 |
|---|---|
| **5** | 能说出「从 __ 到 __ 停在 __」三个坐标;元素全部吸附栏线/三分线/基线;留白 ≥25% 且呼吸位在焦点旁 |
| **4** | 有骨架,1–2 个元素"没有归属" |
| **3** | 动线说得出口,但留白 20–25% |
| **2** | 均质卡片阵列,或留白 <20% |
| **1** | 四边均匀镶边式留白(无意图) |
| **0** | 元素随意摆放,毫无对齐关系 |

### E · 去 AI 味(10%)

| 分 | 标准 |
|---|---|
| **5** | `guardrails.md` 反味自检 12 条全过,且有一处"故意打破"(明显错位/出血/裁切) |
| **4** | 12 条全过,但没有"故意打破",偏保守 |
| **3** | 12 条中 1 条不过(非核心项) |
| **2** | 12 条中 2–3 条不过 |
| **1** | 命中核心项:紫蓝渐变 / AI 高发字体当主标 / 均质卡片墙 |
| **0** | 命中 ≥2 个核心项 |

## 二、及格线

```
及格:加权总分 ≥ 3.5  且  无任何单项 ≤ 1
优秀:加权总分 ≥ 4.5  且  无任何单项 ≤ 2
```

| 结果 | 动作 |
|---|---|
| **优秀**(≥4.5) | 直接交付 |
| **及格**(3.5–4.5) | 交付,在汇报里列出被扣分项的**位置与原因** |
| **单项 ≤1 但总分 ≥3.5** | **必须修**:定位到具体元素,定点修改重导(不重做整图)。修完只重算该维度 |
| **总分 <3.5** | 找出**权重最高且得分最低**的那一维,只修它,重导后再打一次分 |
| **2 轮后仍 <3.5** | 交付并明确列出已知瑕疵(沿用 `pipeline.md` Step 6 的 2 轮上限) |

## 三、与既有清单的映射(不重复维护)

> 本册**不复制**清单条目,只做量化。条目本身仍是唯一真相源。

| 维度 | 唯一真相源 |
|---|---|
| A 层级与焦点 | `style-system.md` §4 信息层级三定律 + `guardrails.md` §2 编辑纪律 |
| B 排版质量 | `typography-rules.md` §一~§五 + §六 排版自检 7 条 + `card-layout.md`(容器越框) |
| C 色彩与对比 | `guardrails.md` §4 色彩规则 + `color-contrast.md`(WCAG 定义与公式) |
| D 构图与留白 | `composition.md` §一 动线 / §二 视觉重量 / §四 网格 |
| E 去 AI 味 | `guardrails.md` §5 反 AI 味自检 12 条 |

> **改稿期的第二种用法(诊断)**:用户说不出哪里不满时,把他的症状词(「不够高级」「太乱」)对到上表某一维,该维就是诊断坐标与动手落点。模糊愿望的诊断 → 翻译 → 减法协议见 `references/revision-protocol.md`。

## 三·五、机械可数规则(数得出来的,别靠感觉)

> 来源:open-design `skills/taste-skill/SKILL.md`(Apache-2.0)。它的口径值得抄:**凡是能数出来的,
> 就不该用形容词判** —— "少用眉题"永远会被忽略,"每 3 节最多 1 个眉题"才管得住。
> 下面是按 artboard 语境翻写的一组,适用对象是**多区块版面**(长图/PPT 页/多段海报/H5):

| 规则 | 数法(机械判定) |
|---|---|
| **眉题(kicker/eyebrow)配额** | 数 `uppercase tracking` 类小标签:**每 3 个区块最多 1 个**;首屏算 1 个 → 9 个区块 ≤3 个 |
| **同一布局族只出现一次** | 整份物料里"图左文右 / 文左图右"这类分栏骨架**最多 2 次连续**,第 3 次连续 = 扣分(改排版族) |
| **格数 = 条目数** | 网格/宫格的格子数必须等于条目数;**中段或末尾出现空格 = 计划错了**,重划网格,别塞占位块 |
| **跑马灯 ≤1/页** | 同页两个以上跑马灯 = 偷懒填充 |
| **同意图一个说法** | 同一意图的行动号召只能有一个措辞("联系我们"+"联络我们"+… 同页 = 失败);导航/主视觉/页脚用同一个 |
| **主视觉文本元素 ≤4** | 眉题(0 或 1)+ 主标(≤2 行)+ 副文(≤20 字/行、≤4 行)+ CTA(1 主 + 最多 1 次) |
| **CTA 不换行** | 桌面宽度下按钮文案必须单行;主 CTA ≤3 个词 |
| **禁用三等分特性卡** | `3 × equal feature cards` 一排 = 一眼模板;改成 1 大 2 小或非等宽 |
| **数字/标签同源** | 页面上出现的编号、期数、页码必须来自同一处数据,不许一处写 "05" 一处写 "五" |

**用法**:首版完成时数一遍(30 秒),不合就改 —— 这些是"**数错就是错**"的硬项,不必等打分。
多区块物料(长图/PPT/H5)按上面数;单张海报只取"主视觉文本元素 ≤4 / CTA 不换行 / 跑马灯 ≤1"。

> **写护栏时的通用教训**(值得抄进所有规则文件):`"少用"` 这种措辞会被忽略。
> 凡是改成**数值或 0/1 禁令**的规则,遵守率立刻不同 —— 本册的阈值、`guardrails.md §5.1` 的七宗罪
> 都用这个写法。写不出来的,说明它还不是规则,只是偏好。

### 前置推理块(动手前先自证一遍)

> 来源:open-design `skills/gpt-tasteskill/SKILL.md`(`<design_plan>` 强制块)。它的做法是
> **先输出自查块,再写代码**,把"我打算怎么做"钉在动手之前。artboard 的对应位置是 Step 1.5
> 设计简报 —— 出图式提示词之外,**加三行自证**(尤其"设计感"需求):

```
【读场一句话】这是什么场合、谁看、要在 3 秒内传达什么
【三旋钮】焦点=____ 层级落差=____倍 强调预算=____处(≤2)
【数学验证】主标最长一行 ____ 字 × 字号 ____px ≈ ____px ≤ 可用宽 ____px(不换行/不掉行)
```

三行写不出来 → 说明需求还没想清,别开写 HTML(回 Step 1 追问或 Step 1.5 重做简报)。

## 四、打分输出格式(写进交付汇报)

```text
【设计评审】总分 4.1 / 5(及格)
A 层级与焦点 4.5 × 30%  — 主标 128px vs 副标 44px(2.9 倍),层级清晰
B 排版质量   3.0 × 25%  — 扣分项:第 3 条要点末行只有 1 个字(孤字),位置 (8%, 61%)
C 色彩与对比 5.0 × 20%  — 正文 7.2:1,强调色只在主标与 CTA
D 构图与留白 4.0 × 15%  — Z 动线成立;扣分项:二维码未吸附右栏线,偏了 18px
E 去 AI 味   4.0 × 10%  — 12 条全过,但缺少"故意打破",偏保守

修复:孤字(改断行点)+ 二维码对齐(贴右栏线),已重导 v2
```

**要求**:
- 每个扣分项必须带**画面位置**(坐标或元素名),不许只写"排版有问题"
- 硬伤项(计 0 的)必须在汇报里点名,不藏在分数里
- 2 轮内的修复只重算被改的维度,不整表重打

## 五、常见误用

| 误用 | 后果 | 正解 |
|---|---|---|
| 每轮改稿都打分 | 违反铁律 5,烧 token | 只在首版完成 / 用户要求时打 |
| 派子代理去打分 | 同上 | 自己打分,不派子代理 |
| 只报总分不报扣分位置 | 用户无法判断值不值得改 | 每个扣分项带坐标 |
| 为了分数堆"故意打破" | 违反「删减哲学」 | E 维 4 分(12 条全过 + 保守)完全可交付 |
| 把 rubric 当设计流程 | 它是验收工具,不是生成工具 | 先按 `composition.md` 构图,再用本册验收 |
