## 4.0 第一原则:矢量是用来"构造"的,不是"描摹"的

矢量图 = **几何关系的组合**。好的矢量图每一根线、每一个角都有理由:对齐某条网格线、
等分某个圆、落在一个比例点上。**说不出构成理由的线,就是噪音**——这是矢量绘制与
"随手放个装饰"的分界线。

**媒介判断**(先选对工具,再谈画法):

| 画面内容 | 用什么 | 理由 |
|---|---|---|
| 能用几何构造描述(圆/方/三角/网格/等分放射/负形) | **矢量**(本册) | 放大不糊、换色改一个 token、可进矢量交付 |
| 写实质感(光影/纹理/食品/人物照片) | **位图**(照片素材) | 写实感来自连续色调与不规则细节,贝塞尔曲线描述它们既低效又假 |
| 人物/吉祥物的插画感 | 素材包优先(`materials.md §4`);自绘走 §4.4 | 自绘只走极简几何/单线语言;写实人物交给照片 |

> **别用矢量硬画照片。**理由:这是工具错配,不是耐心问题——堆再多路径也换不来照片的
> 真实质感,只会得到一张塑料感仿品。一句话判断:**能用几何关系说清楚的,画;说不清楚的,拍。**

## 4.1 CSS 形还是 SVG 路径?(选择判据)

两者都能画几何,判据是**"谁表达这个形状更直接"**:

| 场景 | 用 | 理由 |
|---|---|---|
| 简单几何:矩形/圆/三角/线条 | **CSS**(`border-radius`/`border`/`transform`) | 零标记、tokens 直上、Kiln 支持好 |
| 重复图案底纹(条纹/网点/同心圆/棋盘) | **CSS 渐变**(`repeating-*`,配方见 `effects.md`) | 一行 background,天然平铺可缩放 |
| 复合路径 / 曲线 / 自定义形状 / 图标 | **内联 SVG**(`<path>`/`<circle>`) | 路径精确可控,`currentColor` 全局换装 |
| 真布尔运算(差集/交集/挖孔) | **SVG 原生**(`fill-rule`/`<clipPath>`) | CSS `mask`/`clip-path` 只能"覆盖式裁切",算不出形;仅限 SVG 作独立资产(图标文件/外部插画) |
| **目标产物含矢量交付**(SVG/EPS/AI) | **DOM 盒子几何**(实色/圆角/边框/不透明渐变) | 2026-09-21 实测(§4.5 探针):本管线 Kiln 矢量道把内联 `<svg>` 子树整体栅格化、`transform:rotate` 退化为包围盒;**轴对齐盒子(rect+rx)才是矢量道活下来的形状词汇** |
| conic 类放射/星芒,且要矢量交付 | 换构成:点环/方块放射(§4.2),或改位图交付 | `conic-gradient` 是五禁令第④条;楔形路径只有内联 SVG 能画,而内联 SVG 进矢量道会被栅格化(§4.5) |

> **首选 CSS,只在"CSS 表达不了这个形状"时才上 SVG。**理由:CSS 形零标记零文件,
> scaffold 的 tokens 直通;SVG 路径可读性成本高,别用它画一个 `border-radius` 就能画的圆。

## 4.2 几何构成法:基本形 → 布尔 → 变换

一切复杂几何都是三步:**基本形**(圆/方/三角/线)→ **布尔**(并/差/交)→ **变换**(旋转/复制/阵列)。
动手写码前先把目标形状拆成这三步;拆不出来,说明它多半不是矢量该干的事(回到 §4.0)。

### 布尔与变换:CSS / SVG 双列速查

| 操作 | CSS 写法 | SVG 写法 |
|---|---|---|
| 差集(挖孔) | `mask` / `clip-path: polygon()` | `<path fill-rule="evenodd">`(外形与孔写进同一条路径) |
| 交集 | 多层 `mask` 叠加 | `<clipPath>` + `<use>` |
| 并集 | 多层直接叠加(视觉合并) | 合并为一条 `<path>` 或同组 `<g>` |
| 旋转/复制/阵列 | `transform: rotate()` × N 个元素 | `<use href="#x" transform="rotate(30 12 12)">` |

> **要矢量交付的形状,布尔改用"负空间拼法"**:孔洞 = 盒子拼出的空底(方框挖圆孔 = 四条
> 边盒子围出框,中间空底就是孔)。理由:`evenodd`/`clipPath` 这些 SVG 原生布尔只活在
> "SVG 作独立资产"里;进本管线 HTML 矢量交付,内联 `<svg>` 会被整体栅格化(§4.5 实测),
> CSS mask/clip-path 也活不下去——负空间拼法是唯一全道通行的"差集"。

### 构成四法(让"画得出来"变成"画得好看")

1. **等分**:圆的 6/8/12 等分 → 放射/齿轮/花瓣。呼应 `composition.md` 放射动线(中心偏离
   几何中心 1/6–1/4,正中心=呆);**放射线 ≤24 根**,再多糊成一圈;
2. **栅格**:所有图形吸附同一网格(8/12/24/48px 系),圆心落格点。理由:差 3px 的"差不多
   对齐"读作失误,差 24px 的错位才读作节奏——半对齐是几何构图第一大杀手;
3. **黄金比**:主/次图形的尺寸与位置按 1:1.618(简化 3:5 / 5:8)分配。理由:精致感来自
   **关系可复算**,不是元素本身华丽;
4. **负形**:留白本身就是图形(与 §4.4 正负形同源)。理由:负形是最低成本的"巧"——不增加
   任何元素,只重新分配"什么不被画"。

```html
<!-- 例:等分点环 + 负空间拼框(完整案例见 assets/cases/vector-case.html)
     全部轴对齐 DOM 盒子 —— 矢量道唯一全存的几何词汇(§4.5 实测) -->
<div class="dot" style="left:518px;top:2px"></div>    <!-- 等分:12 枚点,圆心(528,240)
     半径 228,每 30° 一枚(三角函数算坐标,取整 px)…… -->
<div class="bar" style="left:96px;top:336px;width:192px;height:48px"></div>   <!-- 框·上 -->
<div class="bar" style="left:96px;top:480px;width:192px;height:48px"></div>   <!-- 框·下 -->
<div class="bar" style="left:96px;top:384px;width:48px;height:96px"></div>    <!-- 框·左 -->
<div class="bar" style="left:240px;top:384px;width:48px;height:96px"></div>   <!-- 框·右;中空 96×96 = 孔 -->
<!-- .dot{position:absolute;width:20px;height:20px;border-radius:50%;background:var(--c-primary)}
     .bar{position:absolute;background:var(--c-primary)} —— 颜色走 tokens -->
```

> 需要 `evenodd` / `<clipPath>` 真布尔的场景 = SVG 作**独立资产**(图标文件、外部插画)，
> 那里才写 `<path fill-rule="evenodd">`(双列速查表)——不要内联进要矢量交付的 HTML。

**构成纪律(3 条)**:

1. 放射线 ≤24 根(`composition.md` 既有红线);
2. 一张图只用**一套栅格、一个比例关系**——两套栅格 = 两个秩序打架,画面立刻散;
3. 单个图形只做**一次布尔**(外形 + 孔);更复杂的形状拆成多个图形叠放。理由:多层嵌套
   布尔读不出形,只读得出乱——观者不负责解谜。

## 4.3 图标语言统一(Tabler 基准 7 项 + 24px 并排校验)

混用不同来源的图标(有的实心有的描边、线宽 1.5 与 2.5 混排)= 一眼业余。
`assets/icons/` 的 63 枚全是 Tabler——统一到它的语言成本最低,**新画图标也按同一语言画**:

| # | 维度 | 规范(Tabler 基准) | 违反的后果 |
|---|---|---|---|
| 1 | **线宽** stroke-width | 统一 **2**(24 viewBox 基准),不混 1.5/2.5 | 粗细混排,整组发"花" |
| 2 | **圆头语言** | 端点 `stroke-linecap:round` + 拐角 `stroke-linejoin:round`(总是成对出现,合并记忆) | 方头圆头混排 = 两套字体 |
| 3 | **视觉补偿** | 同标称尺寸下,圆形类比方形**略大**(直径 +2%)才等大 | 圆图标永远看着"瘦一圈" |
| 4 | **像素对齐** | 关键坐标落整数 px(24 栅格),避免半像素坐标 | 导出后线条发虚发灰 |
| 5 | **颜色** | `stroke="currentColor"` + CSS `color`(tokens)上色 | 写死 hex,换主题全崩 |
| 6 | **实心 vs 描边** | 一套物料**只用一种**(同 `brand-system.md §五` 第 6 项) | 实心描边混排 = 两套系统 |
| 7 | **栅格框** | 统一 viewBox(24×24),图形四周留等量留白(内容区 ≈20×20) | 有的顶格有的缩一团,大小不一 |

内联模板(Tabler 原样即合规,不要手改属性):

```html
<svg width="24" height="24" viewBox="0 0 24 24" fill="none"
     stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <path d="…"/>
</svg>
```

**缩到 24px 并排校验法**(一组图标画完必做):把整组并排缩到 24px,看三件事——
线宽一致吗?视觉大小一致吗?有没有一枚"重"或"轻"的?
理由:图标缺陷在 48px 以上会被细节掩盖,24px 是图标的"素颜镜"——最小使用尺寸下站得住,图标才成立。

**混源禁令**:同屏不混第二来源的图标(FontAwesome / MD / 系统图标…)。理由:每个图标库的
线宽、端点、透视角度是一套私有语言,单枚再好看,混排整组必乱;缺图标时按 Tabler 语言
**补画一枚**,而不是引入第二套语言。

> **矢量交付注意**:内联图标进 Kiln 矢量道会被整体栅格化为小图(§4.5 实测)——视觉完整、
> 位置正确,但不再是可编辑路径;要"真矢量图标"需在设计工具里以原生路径交付,超出本管线;
> 位图交付(PNG/JPG)完全不受影响。

## 4.4 插画语言(5 种手法 + 与素材包的关系)

| 手法 | 做法 | 适用 | 关键纪律 |
|---|---|---|---|
| **正负形** | 图形与背景互为形状(脸与花瓶),主体与底色都参与造型 | 概念海报、隐喻 | 负形轮廓必须一眼可读;含糊的负形不如没有 |
| **极简几何插画** | 人物/物体拆成圆+方+三角拼装 | 科技/科普/扁平 | 形状词汇 ≤3 种基本形;颜色全走 tokens |
| **手势化** | 粗线条 + 轻微不规则(路径控制点 ±2% 抖动,**不用滤镜**) | 手账/亲切 | 不规则要"构造出来";滤镜糊出来的抖是假手绘 |
| **单线画** | 一笔画完、线宽均匀、不闭合 | 极简/文艺 | 线必须真"一笔"(连续 path);三段拼接的假一笔会被看穿 |
| **可拼装** | 部件化分组(发型/姿势/服装),换部件即换角色 | 吉祥物/人物 | `assets/illustrations/` 的 Open Peeps 就是这门语言的成品库 |

**与素材包的关系**:`assets/illustrations/` 三套(Open Peeps / Open Doodles / unDraw;找图与
改色用法见 `materials.md §4`)是**起点,不是终点**——优先改 fill 换品牌色直接用;素材缺元素时
**按同一语言补画**(如给 unDraw 场景补一枚同语言的几何道具),而不是引入第四套画风。
插画上版后的纪律(色调统一、数量上限)仍归 `materials.md §5`,本册不管上版。

## 4.5 与矢量交付对齐:画的时候就避开五禁令

> 本册所有画法都要能活着过 `vector-export.md §4` 的矢量安全清单。五禁令在**画的时候**避开,
> 比导出后救回来便宜十倍:

| `vector-export.md §4` 禁令 | 画法侧替代 | 为什么禁(理由) |
|---|---|---|
| ① 硬切透明渐变(transparent 端点) | 用不透明等价色(`color-mix` 调到底色),或拆成两段实色 | 矢量端渐变转实色,渐变断裂穿帮 |
| ② mix-blend-mode | 目标色直接算出来写进 tokens(`color-mix` + 对比度复核) | PDF/EPS 无混合语义,整层脏色 |
| ③ 渐变字(background-clip:text) | 文字纯色;渐变感由**背景几何层**承担(渐变在形状上,不在字上) | 矢量化丢字/退纯色 |
| ④ conic-gradient | 位图交付:`repeating-conic` / 楔形 `clip-path` 拼皆可(fx-starburst 原配方);**矢量交付:换构成——点环/方块放射(§4.2)**,内联 SVG 楔形也救不了(进矢量道同样栅格化,见下表) | conic 解析为降级填充,打印即丢 |
| ⑤ alpha 渐变 stop 压圆角 | 阴影/发光与圆角分层(软投影独立一层,不压圆角) | 圆角边界出杂边 |

**结论:矢量绘制三板斧——纯色 + 盒子几何 + 不透明渐变。**需要混合模式/透明渐变的富质感
画面,说明这张图该走位图交付(PNG),五禁令自然不再约束它。

### 矢量道几何边界(2026-09-21 探针实测)

> 探针:`scaffold` 冒烟项目 + 8 项单能力样例,`python scripts/ai_export.py <项目>/src --svg`
> 与 kiln-cli `export --engine native --format SVG` 各导一次、解析 SVG 源码。
> 与 `depth-3d.md §六`(clip-path/mask/text-shadow 的双道矩阵)拼起来是完整边界:

| 画法 | 浏览器 dom 道(auto 默认) | native 道(--engine native) |
|---|---|---|
| 文本 | ✅ 真文本 `<text>` | ❌ 整篇丢弃(输出标 degraded) |
| DOM 盒子实色 / 边框 | ✅ `rect` + stroke 双 rect | ✅ 同左 |
| `border-radius`(含 50% 圆) | ✅ `rect rx`(圆 = rx=宽/2) | ✅ 更好:真 `ellipse` |
| 不透明线性渐变 | ✅ `fill="url(#g)"` 矢量渐变 | ✅ 同左 |
| `transform:rotate` | ❌ 退化为轴对齐包围盒(旋转丢) | ✅ `transform="rotate()"` 保留 |
| `clip-path` / `mask` | ❌ 栅格化为 `<image>` / 丢失 | ❌ 丢失(退回完整矩形) |
| `box-shadow` | ❌ 静默丢失 | ❌ 同左 |
| 内联 `<svg>`(几何 / 图标) | ❌ 整体栅格化为 `<image>` | ❌ 冻结占位块 |

**两道分工**:带文字的海报只有 dom 道可用(文字是海报主体)→ 矢量交付的几何词汇 =
**轴对齐盒子 + 圆角 + 边框 + 不透明渐变 + 真文本**;旋转 / 布尔 / 图标路径三样进矢量稿
要么丢、要么变图。纯几何无文字的资产可走 native 道拿到 `ellipse` 与旋转。
**画法结论**:要矢量交付的图,等分用点环不用旋转射线,挖孔用负空间拼法不用 evenodd,
图标接受"小图内嵌"或改位图交付——都在画的时候选,不到了导出才救。

## 4.6 矢量绘制自检(5 条)

1. **能几何描述吗?**——说不出构成关系(等分/栅格/比例/负形)的"矢量图",多半该换照片(§4.0);
2. **图标语言统一了吗?**——§4.3 七项过一遍;缩到 24px 并排,看不出任何一枚异类;
3. **布尔/遮罩安全吗?**——矢量交付的孔洞用负空间拼法(§4.2),没用 mask/clip-path/内联 SVG 拼形;
4. **颜色走 tokens 吗?**——`currentColor` / `var(--c-*)`,成图没有游离在 tokens 之外的裸 hex;
5. **矢量交付活下来了吗?**——跑 `python scripts/ai_export.py <项目>/src --svg`,打开 SVG 源码:
   盒子几何仍是 `rect`/`ellipse`(旋转/图标栅格化属已知边界,见 §4.5 表)、文字仍是真文本
   (再对拍 `vector-export.md §5` 验收清单)。
