# 双封面版式族详表(六族脚本几何与排版建议)

> **何时读**:`references/formats/gzh-cover.md` 让你选完版式之后;或做出来的封面"还是素"、两张图不像同一栏目。
> **本册是什么**:将用户提供的 18 张封面参考归纳为 6 套 Artboard 版式族。参考图的构图和主次条关系并不完全相同，单张也可能同时带有多族特征；表中的编号表示视觉关联，不表示逐张套用同一模板。
> 六族是可复用的内部排版骨架。坐标以 Artboard 的 900×383 主封面画布为基准，次条画布为 383×383；两者是项目预设，不是微信平台规格。尺寸依据第三方 135 教程，平台展示以当前后台预览为准。参考图编号「参考 12」对应 `封面参考 (12).jpg`。
> **本册不管什么**:导出纪律/合并图 → 主册;色值 → `scripts/_gzh_theme.py`(唯一色源);通用铁律 → `guardrails.md`。

### 0.2 选族判据(按顺序问,命中即停)

1. 需要把本地照片作为构图主体? → `plate-page`;必须提供本地 PNG/JPEG/WebP。日期、地点、主办方等元信息可放入文字栏,但不是选用该族的硬性条件。
2. 标题短,希望标题本身成为画面主体? → `giant-caps`。
3. 主封面需要明确的副题和左侧文字面板? → `band-editorial`;该族的 `check` 要求填写主封副题。
4. 活动、招募或迎新,希望采用卡片层级? → `stack-cards`。偏手作纸感可选 `kraft-note`。
5. 通知、通稿、喜报等希望简洁稳重? → `center-band`。
6. 以上都不命中时,从标题长度、配图和视觉语气中选择。六族是 Artboard 的内部排版骨架,不是对 18 张参考图共同模板的断言。

### 0.3 约束叠加顺序

```
① 当前后台预览中的实际显示效果  →  ② 版式族安全区与几何(本册 §§2-8)
→  ③ 标题行数、断行与字号下限  →  ④ 可选装饰与主题 tokens
→  ⑤ 用户内容与层级优先;平台显示不确定时以当前预览为准
```

## 一、内部安全规则与排版建议

18 张参考图不是同一套模板的变体。下面是 Artboard 的排版建议;实际安全框和标题行数按具体版式族执行,不要把建议误读为平台裁切规则。

| # | 规则 | 判据 |
|---|---|---|
| **1** | **正文优先放入 `.safe`**:主标题、眉题和副题按各族的安全框排布 | 主封面检查框须落在项目内部中央区域;次条检查框须满足内部边距要求 |
| **2** | **安全框外少放关键信息**:画布边缘留给背景、色块或可裁去的装饰 | 这是 Artboard 保守的排版约定,不代表微信列表或分享卡片固定如何裁切 |
| **3** | **层级按内容取舍**:可使用眉题、主标题、副题、期号等,不要求每张恰好三层 | 装饰与辅助信息可省略,不应挤压主标题 |
| **4** | **颜色服务于主题**:优先使用 `_gzh_theme.py` 提供的主题色和强调色 | 具体色值由主题配置提供,本册不另行规定色相数量 |
| **5** | **装饰从简**:带、卡片、贴纸、徽标、纹理等按版式语气选择 | 装饰数量是视觉建议,不是脚本统一限制 |
| **6** | **主次条保持栏目感**:默认复用主题、字体和视觉母题,按次条画布重新排版 | `same`、`minimal`、`flat` 可采用不同程度的简化,不要求逐项复制主封面 |

> 本册所说的 383px 安全宽度和 900×383、383×383 画布,均为 Artboard 的保守内部选择,参考第三方 135 教程中的做法。它们不代表微信或 135 对裁切位置、裁切方向或尺寸的保证。平台展示规则可能变化,发布前请以当前公众号后台预览为准。

## 二、画布与安全区

### 2.1 画布基准与来源

`gzh_cover.py` 使用 900×383 主封面和 383×383 次条作为 Artboard 内部画布。第三方 135 教程展示了相近尺寸和安全区做法,但平台官方资料未确认这里的尺寸或固定裁切位置。可参考 [135 教程(2025)](https://www.135editor.com/essences/10593.html) 和 [135 教程(2020)](https://www.135editor.com/essences/4832.html);发布前请检查当前后台预览。

主封面中央 383px 的内部参考范围是 x=258.5 至 641.5。它是保守排版区,不是微信或 135 保证显示的中央裁切框。脚本 `check` 对主封面 `.safe` 的 x 范围要求约在 258 至 642 内,并要求上下留出至少 20px;各族的精确盒子见下表。

### 2.2 六族主封面的 `.safe` 盒子

| 版式 | x | y | 宽 × 高 | 版式中的主要几何 |
|---|---:|---:|---:|---|
| `center-band` | 258.5-641.5 | 30-353 | 383 × 323 | 色带 x=258.5-641.5,y=96-328,高 232px |
| `band-editorial` | 274-622 | 30-353 | 348 × 323 | 左侧面板 x=0-642,全高 |
| `stack-cards` | 282-618 | 80-303 | 336 × 223 | 卡片 x=258,y=48,384 × 287;内带宽 336px、高 80px,y=80 |
| `giant-caps` | 258.5-641.5 | 30-353 | 383 × 323 | 主标题在该框内居中排布 |
| `kraft-note` | 262-610 | 26-357 | 348 × 331 | 标题可有轻微旋转,排版仍按安全框拟合 |
| `plate-page` | 272-624 | 26-357 | 352 × 331 | 右侧照片窗 x=672-900,全高 |

`check` 的安全区断言只针对脚本可解析的 `.safe` 盒子。具体标题还需满足该族的列宽、行数与字号要求;安全框外的色块、照片和装饰不等于信息区。

### 2.3 六族次条安全框

| 版式 | `.safe` x | `.safe` y | 宽 × 高 | 版式中的主要几何 |
|---|---:|---:|---:|---|
| `center-band` | 34-349 | 24-359 | 315 × 335 | 色带 x=17-366,y=17-366,349 × 349 |
| `band-editorial` | 56-351 | 22-361 | 295 × 339 | 文字在次条内偏左排布 |
| `stack-cards` | 50-333 | 45-338 | 283 × 293 | 卡片 x=28,y=28,327 × 327;内带宽 283px |
| `giant-caps` | 38-345 | 24-359 | 307 × 335 | 标题最多四行 |
| `kraft-note` | 38-345 | 26-357 | 307 × 331 | 标题可轻微旋转,宽度按安全框拟合 |
| `plate-page` | 34-240 | 26-357 | 206 × 331 | 右侧照片窗 x=260-383,全高 |

次条 `check` 要求 `.safe` 左右至少留出画布宽度的 8% (约 30.6px),上下至少 20px。各版式按自己的列宽排字,不能把整张 383px 方图都当作标题宽度。

### 2.4 次条字号与版式模式

`SUB_SCALE=0.62` 是次条字号的参考上限,不是次条标题必须精确等于主封标题的 62%。次条先按本族列宽拟合,再受主封标题字号乘 0.62 的上限约束;标题最小字号为 22px。若列宽、行数与下限无法同时满足,`check` 会判定不合格,不能只靠缩小画布解决。

`--sub-mode` 取值为 `same`、`minimal`、`flat`。`same` 沿用同族次条版式与主题装饰;`minimal` 只保留次条标题;`flat` 使用纯主题底色,去掉底纹、着色器和装饰,标题与副题改用清晰的主题文字色,但仍保留 `plate-page` 照片。`flat` 不是"不显示图片"模式。

## 三、族 1 · `center-band` 居中色带(无副题时默认)

> 参考:4、5、7、9、17。通过 `gzh_cover.py --layout center-band` 显式选择；直接运行 `gzh_cover.py new` 不传 layout 仍走 legacy 兼容模板。文章转换的 `--cover-layout auto` 在没有 `--cover-sub` 时选此族，有主封副题时切至 `band-editorial`。

**一句话**:一张安静的全底色底子,中央 383px 内部安全区里压一条**横向色带/白卡**,字坐带上;
其余一律是背景肌理。适合通知、通稿、喜报、每日资讯等"信息本身很硬,不需要花"的稿。

**信息形态**:2-3 层。眉题(可空)+ 主标 + 副题(可空)。

### 3.1 几何与标题拟合

| 元素 | 脚本几何 / 排版 |
|---|---|
| 主封画布与底色 | 900×383px 内部画布,主题底色 |
| 主封 `.safe` | x=258.5-641.5,y=30-353,宽 383px |
| 中央色带 | x=258.5-641.5,y=96-328,383×232px |
| 主封标题 | 最多 2 行,建议每行不超过 8 字;基准字号 54px,按 360px 列宽拟合,该族拟合下限 26px |
| `check` 行数上限 | `TITLE_ROW_CAP=3`;这是显式换行检查上限,不等同于推荐的两行排版 |
| 次条 `.safe` | x=34-349,y=24-359,宽 315px;色带为 349×349px,x=17,y=17 |
| 次条标题 | 最多 2 行,建议每行不超过 6 字;基准字号 44px,按本族列宽拟合,该族拟合下限 24px,再受 `SUB_SCALE` 上限约束 |

### 3.2 可选视觉处理(人工建议,非脚本固定输出)

- **底纹**:`dots` 点阵(半透明,间距 18px,右上角 200×160 范围)或 `glow` 单束弧光(从左上到右下的柔光带)。
- **水印**:可选短英文(建议 ≤10 个字母),水平字旋转后放在左侧装饰外围区,透明度 8%;必须完整留在画布内,不得侵入主标或页脚安全区。
- **标记(标记形状)**:色带左侧 44×8 的实色短条(与主题 accent 同色);或色带本身即标记(那就**去掉**短条,别重复)。
- **页码/期号**:右侧 800 处 64px 数字,透明度 30%。

### 3.3 选用提示

- 标题很长且必须单行时,选择更宽的标题排版或先压缩文案,不要依赖自动换行满足审美要求。
- 需要照片作为主体时改用 `plate-page`;若只需热闹的卡片层次,可选 `stack-cards` 或 `kraft-note`。

### 3.4 次条联动

- `same` 或 `minimal` 可保留色带语言;`flat` 会去掉装饰色带。无论模式如何,标题都按 383×383 画布及 315px 安全列重新拟合,字号受主封标题的 0.62 倍参考上限约束,不是机械缩放。
- 其他装饰可省略或精简;实际显示由 `--sub-mode` 决定。

## 四、族 2 · `band-editorial` 左文带

> 参考:1(大字块+黄底副题条)、2(左文右图+副题拼音)、6(斜置大字块+双行副题)、13(便签横带+角标)、18(手写大字+棕底胶囊)。
> 这是适合主标题加副题的左文带排版。主封面副题是必要内容,`gzh_cover.py check` 会在此族缺少主封副题时报告 `layout-content-fit`。

**一句话**:左侧面板延伸至 x=642,标题文字放入面板内偏左的安全栏;照片不是该族的必需素材。

### 4.1 几何与标题拟合

| 元素 | 脚本几何 / 排版 |
|---|---|
| 左侧面板 | x=0-642,y=0-383,全高 |
| 主封 `.safe` | x=274-622,y=30-353,宽 348px |
| 主封标题 | 左对齐,最多 2 行,建议每行不超过 6 字;基准字号 60px,按 348px 列宽拟合,下限 26px |
| `check` 行数上限 | `TITLE_ROW_CAP=3`;显式换行上限,不表示建议填满三行 |
| 主封副题 | 必须提供;它是 `layout-content-fit` 检查条件,副题字数本身不由该检查项设上限 |
| 次条 `.safe` | x=56-351,y=22-361,宽 295px |
| 次条标题 | 最多 2 行,建议每行不超过 5 字;基准字号 33px,本族拟合下限 24px,再受 `SUB_SCALE` 上限约束 |

### 4.2 可选视觉处理(人工建议,非脚本固定输出)

- **底纹**:`stripe` 45° 细斜纹(2px 线,间距 12px,透明 5%)或纯色。
- **水印**:带左侧 x=200 处的竖排栏目标签(`writing-mode: vertical-rl`,字距 0.5em,14px)。
- **标记**:眉题前的 `→→`(纯 CSS 画,别用字符图标);或主标首字下沉式色块。
- **角标**:期号斜贴(旋转 −4°)。

### 4.3 选用提示

- 主标题很短时,`giant-caps` 或 `center-band` 可能更简洁。
- 主封副题缺失时,`check` 会判定本族内容不满足要求;不需要副题可改选其他族。

### 4.4 次条联动

- 次条按 295px 安全列独立排版,最多两行,建议每行不超过 5 字;字号在本族拟合后再受 0.62 倍上限约束。
- 是否保留副题或装饰取决于实际文字和 `--sub-mode`,不要求主次条逐项复制。

## 五、族 3 · `stack-cards` 分层堆叠

> 参考:3(蓝底+白卡+浏览器三点+角标)、5(蓝底+白卡+圆孔+星光)、13(黄底+蓝撕边+白便签+两枚角标)、14(蓝底+跑道分层)。

**一句话**:色底上叠一张卡片,卡片内再用色带承载标题,形成清楚的层次。圆角、直角或撕边是视觉选择,不要求所有形状完全一致。

### 5.1 几何与标题拟合

| 元素 | 脚本几何 / 排版 |
|---|---|
| 主封卡片 | x=258,y=48,宽 384px,高 287px |
| 主封 `.safe` | x=282-618,y=80-303,336×223px;内色带 x=282,y=80,宽 336px,高 80px |
| 主封标题 | 建议最多 2 行,每行不超过 5 字;基准字号 46px,按 331px 列宽拟合,下限 22px |
| `check` 行数上限 | `TITLE_ROW_CAP=4`;显式换行上限,高于常用排版行数 |
| 次条卡片 | x=28,y=28,327×327px;内色带 x=50,y=45,宽 283px,高 56px |
| 次条 `.safe` | x=50-333,y=45-338,宽 283px |
| 次条标题 | 最多 4 行,建议每行不超过 4 字;基准字号 30px,按 283px 列宽拟合,下限 22px,再受 `SUB_SCALE` 上限约束 |

### 5.2 可选视觉处理(人工建议,非脚本固定输出)

- **形状标记**:卡片顶部的"三点圆圆"(浏览器窗感)、角上的折角、撕边,三者**选一种**,不要都上。
- **贴纸**:1 枚旋转 −6° 的胶囊(带 "NEED YOU" 式英文 2 词),压在卡边。
- **星/点**:2-3 个小星点(`✦` 字形用 CSS 画,或用 Tabler SVG 内联),只放在空角。
- **水印**:白卡后面的大字(被卡片遮住一半,露出边缘=高级感)。

### 5.3 选用提示

- 若画面需要纸张手作感,可考虑 `kraft-note`;不必把两种装饰语言叠在一起。
- 次条卡片按 327px 方卡和 283px 安全列排版,不要照搬主封面的 384px 卡片几何。

### 5.4 次条联动

- 次条使用 327×327px 卡片,在 283px 安全列内排标题;最多四行,每行建议不超过 4 字。
- `same` 或 `minimal` 可保留与主封相近的卡片母题;`flat` 会去掉装饰卡片。是否保留其他装饰按内容和 `--sub-mode` 取舍。

## 六、族 4 · `giant-caps` 巨字压边

> 参考:2(90周年 巨号数字 + 三层字)、3(紧急招募 4 字占满)、4(字号最大的一族)、6/7(白字压底)、9(倡议书 3 字)、17(每日资讯)。**"字即画布"那一族。**

**一句话**:主标题占据版面中心,让字本身成为主要视觉形状;适合短而有力的标题。

### 6.1 几何与标题拟合

| 元素 | 脚本几何 / 排版 |
|---|---|
| 主封 `.safe` | x=258.5-641.5,y=30-353,宽 383px |
| 主封标题 | 标题不超过 5 字时优先单行;更长时最多 4 行,按最长一行和总行数计算字号,以约 340px 总高度预算拟合 |
| `check` 行数上限 | `TITLE_ROW_CAP=4`;全局最小字号检查为 22px |
| 次条 `.safe` | x=38-345,y=24-359,宽 307px |
| 次条标题 | 最多 4 行,建议每行不超过 4 字;按本族列宽与行数拟合,参考下限 24px,再受 `SUB_SCALE` 上限约束 |

### 6.2 标题视觉处理

- 短标题优先单行,给大字留出安全框内的呼吸空间。
- 多行标题按语义断开并尽量平衡各行长度。错位排版、描边或水印属于可选的人工视觉处理,不是 `giant-caps` 固定生成的子变体。

### 6.3 可选视觉处理(人工建议,非脚本固定输出)

- **描边字**:主标用 `-webkit-text-stroke`,描边宽 **≤字号 1%**(150px → 1.5px);**中文粗体禁细描边**(`typographic-expression.md §八` #3)。
- **底纹**:`arc` 弧光(右上一束柔光)、`grain` 颗粒噪点(`repeating-radial-gradient` 或用 SVG filter 噪点)。
- **角章**:1 枚旋转 −6° 的期号贴纸。
- **水印**:英文长词(≤10 字母),与主标**同字号**,填充 8% 透明度,垫在主标后。

### 6.4 选用提示

- 标题较长时,按最多 4 行的布局规则拟合;脚本的标题长度检查上限为 20 字。超过后应精简标题,而不是继续压缩字号。
- 日期、地点等信息可以作为辅助文字,但应遵守安全框和整体层级,不要与大标题争夺焦点。

### 6.5 次条联动

- 次条标题在 307px 安全列内重新拟合,最多四行,推荐每行不超过 4 字;字号受主封字号的 0.62 倍参考上限约束。
- 日期、徽标等辅助信息按空间选择保留或省略,不是此族必须元素。

## 七、族 5 · `kraft-note` 牛皮便签

> 参考:11(牛皮底 + 邮票贴纸 + 撕纸 + 手写体 + 英文水印)、12(纸纹 + 毛笔字 + 烟花)、16(洒金底 + 花枝 + 描边框)、18(牛皮底 + 手写 opening + 小图卡)。

**一句话**:纸感、轻微倾斜和手作细节可营造便签气质;手写体、撕边、阴影等是参考图中的视觉手法,并非固定输出。

### 7.1 几何与标题拟合

| 元素 | 脚本几何 / 排版 |
|---|---|
| 主封 `.safe` | x=262-610,y=26-357,宽 348px |
| 主封标题 | 最多 2 行,建议每行不超过 6 字;基准字号 62px,按 348px 列宽拟合,计入 0.92 的旋转宽度余量与 1.06 的行高余量,最小拟合字号 22px |
| `check` 行数上限 | `TITLE_ROW_CAP=3`;显式换行上限,常用排版仍建议不超过两行 |
| 次条 `.safe` | x=38-345,y=26-357,宽 307px |
| 次条标题 | 最多 2 行,建议每行不超过 5 字;基准字号 38px,本族拟合下限 22px,再受 `SUB_SCALE` 上限约束 |

### 7.2 可选视觉处理(人工建议,非脚本固定输出)

- **纸纹**:`grain` 噪点(低对比)或斜纹 + `mix-blend-mode: multiply`。
- **撕边**:用 `clip-path: polygon(...)` 的 12 点扰动做出"撕纸"边,只在一处用。
- **贴纸阴影**:`box-shadow: 0 6px 18px rgba(0,0,0,.12)`,**每张纸一个**,不叠加。
- **手写体**:必须来自 fonts/(`lxgw-wenkai` / `liyu-shoushu` / `chill-zhuo-kai` / `zcool-kuaile`),**禁 CSS 斜体冒充手写**。

### 7.3 选用提醒

- 深底主题也能使用纸感,但应控制纹理对比,避免底色和纸纹互相争抢。
- 标题较长时,手写大字可能难以辨认;先按两行和实际列宽试排,必要时缩短标题或改用其他族。
- 只放一张贴纸而没有其他图形时,注意补足画面重心,避免显得空。

### 7.4 次条联动

- 次条按 x=38-345、y=26-357 的 307px 安全列重新排版;标题最多两行,建议每行不超过 5 字。
- 便签底、描边胶囊或贴纸可按 `--sub-mode` 取舍,不要求把主封装饰等比缩小。

## 八、族 6 · `plate-page` 画页分栏

> 参考:15(图片出血成页 + 左右竖排标签 + 英文大标 + 日期线)、2(人像出血 + 主文左栏)、10(手绘插画出血 + 描边字)、16(花枝跨栏)。

**一句话**:把本地照片放进右侧图窗,左栏排标题和辅助文字,形成杂志内页式分栏。照片是此族的必需素材,不是可选背景。

### 8.1 图片要求、几何与标题拟合

- `gzh_cover.py new --layout plate-page` 必须提供本地 PNG、JPEG 或 WebP 文件;缺少 `--image` 时会报 `IMAGE_REQUIRED`。图片上限为 50 MiB,并须完整解码验证,无效内容会报 `IMAGE_DECODE_FAILED`;脚本将有效素材复制到项目的 `src/images/` 目录。
- 主封 `.safe`:x=272-624,y=26-357,宽 352px;右侧照片窗 x=672-900,全高 383px。
- 主封标题:最多 2 行,建议每行不超过 5 字;基准字号 50px,按 352px 列宽拟合,下限 24px。`TITLE_ROW_CAP=3` 是 `check` 的显式换行上限,不是推荐行数。
- 次条 `.safe`:x=34-240,y=26-357,宽 206px;右侧照片窗 x=260-383,全高 383px。
- 次条标题:最多 2 行,建议每行不超过 4 字;基准字号 30px,本族拟合下限 22px,再受 `SUB_SCALE` 上限约束。
- 图片按图窗尺寸铺放;主封与次条图窗宽高比不同,须分别检查主体是否合适。此处是 Artboard 内的图片布局,不代表平台对整张封面的裁切方式。

### 8.2 可选视觉处理(人工建议,非脚本固定输出)

- **出血图**是主装饰(算 1 件)。
- **竖线/横线**:发丝线(1px,border)分隔信息段,学杂志。
- **竖排标签**:左右各 1 条(或只一条),内容为栏目名/主题词。
- **色板**:主标后可垫一块半透色板(参考 15 的橙色蒙版),保证对比度。

### 8.3 选用提示

- 没有本地 PNG/JPEG/WebP 图片时,不能使用 `plate-page`;改选不依赖图片的版式,或先准备素材。
- 若照片主体与窄图窗不匹配,更换素材或版式,不要假设平台会以某个固定方向裁切。
- 主标题建议控制在两行内,并按 352px 主栏宽度拟合。

### 8.4 次条联动

- 次条使用同一 `--image` 素材,但放入 x=260-383 的窄图窗;不能将其称为方形裁切或假定与主封主体位置一致。
- 次条元信息按完整字段换行,避免拆开日期、地点或专名;字段过长时精简或省略非必要信息。
- 按实际预览分别检查主封和次条的主体构图。字号受主封标题字号的 0.62 倍参考上限约束,不是固定缩放。

## 十、内容设计建议与脚本检查

### 10.1 标题断行与字号拟合

主标题按版式族的文字列宽与行数拟合,不要用统一的「字数换字号」表覆盖各族。下面的行数和每行字数是排版器的计划目标;`check` 的 `title-row-cap` 是显式换行上限,`title-min-px` 的全局下限为 22px。

| 版式族 | 主标题计划 | 主封基准字号 / 拟合下限 | 次条标题计划 | 次条基准字号 / 拟合下限 |
|---|---|---|---|---|
| `center-band` | ≤2 行,目标每行 ≤8 字;检查上限 3 行 | 54px / 26px,在 360px 列宽内拟合 | ≤2 行,目标每行 ≤6 字 | 44px / 24px,315px 列宽 |
| `band-editorial` | ≤2 行,目标每行 ≤6 字;检查上限 3 行 | 60px / 26px,348px 列宽 | ≤2 行,目标每行 ≤5 字 | 33px / 24px,295px 列宽 |
| `stack-cards` | ≤2 行,目标每行 ≤5 字;检查上限 4 行 | 46px / 22px,331px 列宽 | ≤4 行,目标每行 ≤4 字 | 30px / 22px,283px 列宽 |
| `giant-caps` | ≤5 字时优先单行;更长标题最多 4 行,目标每行 ≤5 字;检查上限 4 行 | 随最长行和总行数计算,总高预算 340px | ≤4 行,目标每行 ≤4 字 | 按 307px 安全列拟合,下限 24px |
| `kraft-note` | ≤2 行,目标每行 ≤6 字;检查上限 3 行 | 62px / 22px,348px 列宽,计入旋转余量 | ≤2 行,目标每行 ≤5 字 | 38px / 22px,307px 安全列 |
| `plate-page` | ≤2 行,目标每行 ≤5 字;检查上限 3 行 | 50px / 24px,352px 列宽 | ≤2 行,目标每行 ≤4 字 | 30px / 22px,206px 列宽 |

全局 `check` 限制主封和次条标题各自最多 20 个可见字符。排版器优先在语义边界断行,避免拆开锁定词组、把单字或双字留成孤行,以及把助词放到行首或行尾。`--title` 中的 `\n` 用作显式换行,并受该族的行数上限检查;无法自动找到合适断点时,仍须通过宽度检查并查看实际渲染,不能只看字符数。

### 10.2 副题与次条标题

主封 `--sub` 是副题,次条副题使用 `--sub-sub`;脚本没有统一的副题字符数或最小字号上限,建议保持精炼,并在对应版式的内容区内预览。`band-editorial` 的主封必须提供副题,因为该族的文字带需要副题补足信息密度。次条标题使用 `--sub-title`,未填写时默认沿用主封标题。

次条字号受 `SUB_SCALE=0.62` 约束,但这是相对主标题字号的参考上限,不是必须精确缩成 62%。每个版式先按自己的列宽拟合;次条标题的全局最小字号为 22px,部分版式使用更高的拟合下限。列宽、行数和下限无法同时满足时应缩短文案或换族,不要只压小字号。

眉题、胶囊、竖排标签、英文水印的字数建议属于视觉取舍,不是 `gzh_cover.py check` 的统一硬限制。

### 10.3 信息层级与标记

- 眉题、主标、副题可形成「弱、强、弱」的层级,但是否需要三者由文案和版式决定;只有 `band-editorial` 的主封副题是脚本检查的必需项。
- 期号、页码和徽标是可选信息。不要把它们固定放在某个画布边缘坐标,也不要把安全区外的文字误当作平台必裁区域。
- 数字与年份尽量统一写法和来源,避免同一信息在主标与徽标中重复或互相矛盾。

### 10.4 元素数量建议

以下是人工审稿时的复杂度参考,不是脚本的元素计数上限。主次条的可读性取决于具体字号、图形和文字列宽,无需为了满足统一件数而删改。

| 产物 | 视觉建议 | 复核方式 |
|---|---|---|
| 主封面 | 信息层级清楚,装饰不抢主标 | 检查标题和辅助文字的实际字号、对比度与留白 |
| 次条 | 优先保留标题及必要识别信息 | 缩小预览,确认文字仍可辨 |
| 强调色 | 少量重复,保持主题色关系 | 检查色块、胶囊与标题是否争抢焦点 |
| 字体与特效 | 控制字体数量,避免描边、阴影、纹理叠加过多 | 按画面实际效果取舍 |

### 10.5 留白与安全区

- 为标题和辅助信息保留呼吸位,避免文字挤满内容列;具体 `.safe` 边界按 §§3-8 的版式坐标执行。
- `gzh_cover.py check` 检查脚本可解析的 `.safe` 盒子和标题拟合等几何条件,不会替代视觉判断,也不表示安全区外内容会被平台裁去。
- 背景、色块、照片或装饰可以延伸到 `.safe` 之外,但应确保标题和必要信息留在对应版式的内容区内。

### 10.6 色彩建议

- 配色以主题底色、文字色和少量强调色为主,减少彼此争抢的高饱和色。
- 深底主题的浅色文字通常用于保证对比度;具体颜色以脚本主题和素材实际表现为准。
- 冷暖色同时出现时,用插画、照片或明确的层级关系把它们整合起来,不要让强调色互相打架。

### 10.7 离线资源与可执行内容

- `gzh_cover.py check` 会拒绝 `<base>`、未审计的内联脚本、事件处理器、`srcdoc`、未审计脚本源及外部资源。静态封面也拒绝 CSS `animation`/`keyframes`,避免隐藏动画在截图时导出空白。例外仅为生成器使用的本地 `vendor/shaders/upstream.js` 和 `runtime.js`;脚本必须解析到实际 vendor 根且命中固定 SHA256,不要给自定义脚本加白名单。
- CSS 的 `url()`、`@import`、`image-set()` 和 HTML URL 属性均受离线检查;相对文件引用须规范化后位于 `src/` 或明确授权的 Skill 资产根,`../` 越界和本机 `file:` URL 都会拒绝。水效 `shapeSdfUrl` 使用项目内可打包资源或允许的内嵌 raster data,不可指向 HTTP(S)、file 或其它外部 scheme。
- 静态导出还要求 `.poster` 是 `<body>` 的直接子元素（不允许可隐藏的包装祖先），标题不能被 CSS 隐藏，且仅允许固定层级的内建 `::after` 纹理；`video`、`audio`、`marquee` 和多帧图片会被拒绝。`img`/兼容别名 `image` 指向的本地栅格资源必须存在且可完整解码。
- 这些是 Artboard 导出门禁,不等同于平台规则;检查后仍应实际渲染并检查产物。

## 十一、主次条联动建议

1. 默认用 `--sub-mode same` 沿用同族次条版式;`minimal` 只保留标题,`flat` 切为纯主题底色并去掉底纹、着色器和装饰,但保留 `plate-page` 照片。
2. 主次条可以沿用相同字体和视觉母题,但次条不是主封面的等比缩小。各自按自己的画布和安全列排版,装饰可删减,也可按版式需要重新安排。
3. `SUB_SCALE=0.62` 是次条标题的相对字号上限参考,不是精确缩放比例。见 §10.1 的族别拟合;低于 22px 的标题不合格。
4. `plate-page` 主封与次条使用同一 `--image` 素材,但图窗尺寸不同,应分别检查图像主体;其他版式不要求图片联动。
5. 主次条断行可以不同。优先保留语义完整的词组,避免把助词放到行首或行尾;`gzh_cover.py check` 会检查标题断词和助词边界,并限制显式换行行数。
6. 装饰数量、标记形状、期号和副题都按实际需要取舍,没有脚本规定的统一件数上限或必须同款规则。
7. 发布前以当前后台预览确认主封、次条各自的可读性和照片构图;不假设平台会固定居中、向左或按某个精确比例裁切。

## 十二、人工视觉复核建议

以下是视觉取舍,不是脚本硬性禁则。必要信息应放在对应版式的 `.safe` 内容区内,外围装饰则按构图需要安排;安全区外的任何内容都不代表会被平台裁切。

1. 避免炫光或发光字压过主标;装饰光效若保留,应和文字层级区分。
2. 插画式人物、物件与 emoji 风格图标的质感不同,混用时检查整体是否协调。
3. 控制字体数量,手写体与正文、展示字搭配时检查辨识度。
4. 贴纸、旋转和多个标题强调手法都应服务于构图,避免出现多个互相争抢的焦点。
5. 装饰与文字靠近 `.safe` 边界时,检查是否产生碰撞或看似意外的遮挡。
6. 标题箱、描边字和贴纸同时出现时,确认主次关系清楚。

## 十三、视觉案例(概念草图,非脚本默认输出)

以下案例保留参考图的视觉构想,不保证按表格数值直接生成相同成图。画布、`.safe` 坐标、标题拟合和次条样式以 §§2-8 及脚本检查为准。

### 案例 A · 通知类,`center-band`

```
标题:2026 春节放假通知
眉题:NOTICE
副题:2 月 15 日至 2 月 22 日
主题:red
```

| 元素 | 概念处理 |
|---|---|
| 底与色带 | 使用 `red` 主题,在画布中央放置 `center-band` 的 383×232 色带,y=96 |
| 眉题与主标 | `NOTICE` 作短眉题;主标题按语义分行,在 360px 标题列内拟合 |
| 副题 | 日期作简短副题,在当前版式安全区内排版 |
| 装饰 | 可在外围加入低对比度年份水印或短线,必要信息仍留在 `.safe` 内 |

**次条**:按 383×383 画布和该族次条安全列独立拟合标题。可用 `minimal` 简化装饰;不要求精确按主封比例缩小。

### 案例 B · 招募类,`giant-caps`

```
标题:紧急招人
副题:寻找发光的你
章:NEED YOU
```

| 元素 | 概念处理 |
|---|---|
| 主标 | 四字标题优先尝试单行,字号由文字列宽和总高拟合,不沿用固定字号 |
| 副题 | 以短句补充招募语气,留在内容安全区内 |
| 装饰 | 可选用低对比度英文水印或徽标,但不让装饰成为第二个主焦点 |

**次条**:按 `giant-caps` 次条宽度与行数重新计算标题字号;可选择 `minimal` 或 `flat`,不是主封的等比缩小件数清单。

### 案例 C · 活动类,`kraft-note`

```
标题:音为有你 新程共响
副题:可画大学 2025 级迎新晚会
贴纸文案:KEEP WANDERING
```

| 元素 | 概念处理 |
|---|---|
| 底与纸感 | 可用 `warm` 主题与低对比度纸感纹理,作为便签视觉的辅助层 |
| 主标 | 在主封 348px 文字列内按语义分成两行,保留手作气质但以实际拟合字号为准 |
| 副题与贴纸 | 日期、地点或短标签可作辅助信息;贴纸是可选装饰,不要求固定数量或坐标 |

**次条**:在本族 307px 安全列内重新排版。主副标题与贴纸可按 `--sub-mode` 取舍,字号仍由列宽和 `SUB_SCALE` 上限共同决定。

## 十四、自检清单(交付前)

1. 选定的族是否符合文案与素材?`plate-page` 是否提供本地 PNG/JPEG/WebP 图片?
2. 标题是否留在该族 `.safe` 内,字号能否通过宽度与最小值检查?
3. 显式换行是否符合该族计划行数和 `TITLE_ROW_CAP`?语义词组与助词是否断得自然?
4. 主封与次条标题是否各自不超过 20 个可见字符?必要时是否缩短文案或更换版式?
5. `band-editorial` 是否提供主封副题?
6. 次条标题是否按自己的安全列拟合,没有把 `SUB_SCALE=0.62` 当成必须比例?
7. 若用了 `--sub-mode flat`,是否确认它会去掉次条装饰与主题效果,但保留 `plate-page` 照片?
8. 安全区外的文字是否只是无需依赖平台裁切结果的辅助信息?
9. 缩小预览时,主次条标题与必要信息是否仍清楚?
10. 删除一件装饰后,画面是否更清楚?如是,删去它。
11. 视觉是否保留素材自身特点,避免不必要的发光、渐变字或装饰性英文?
12. 发布前是否检查当前公众号后台预览,而不是假定固定的裁切位置或尺寸?

> 可用 `python scripts/gzh_cover.py check <slug>` 执行脚本支持的几何与标题检查。它不替代浏览器渲染、视觉判断或平台预览。
