# 交付后审阅(审片台)· 意见文件即 Agent 接口

> **何时读**:① 用户说"审片 / 挑问题 / 逐帧看 / 我看看这段 / 给点意见 / 哪里不对劲"时;
> ② 交付了动效/视频卡/长动效之后,要进"看片 → 提意见 → 改稿"闭环时;
> ③ 在做**多轮返修**的 MV / 宣传片 / 长动效时(模式 V,见 `video-motion.md`)。
> 工具在 `tools/review-station/`(说明见该目录 README);本册给**口径与通用铁律**。
>
> 来源:MV 审片台资产包(`world.execute(me);`,2160p60、200+ 场景、33 轮返修)的
> 20 条审片台铁律 + 8 条渲染铁律 + 4 条诊断方法论,按 artboard 口径提炼。逐条标注
> 【通用】(换任何项目都成立)/【专属】(原工程的文件名、帧号、字体,移植时不要照抄)。

---

## 〇、这一段补的是什么

artboard 原有流水线终点是 Step 7 "交付":把成品图/视频交给用户。**交付之后就没有了** ——
用户说"这段有问题"时,只能靠人肉转述(截图 + 口头描述),Agent 再去猜是哪一秒、哪个元素。

本册补的正是这一段,四件事:

| # | 能力 | 一句话 |
|---|---|---|
| 1 | **交付物可审阅化** | 成片/长动效不再是一个 mp4,而是能拖时间轴逐帧看、能缩放轨道定位到句、能切字幕轨对照的网页 |
| 2 | **元素级批注** | 像 F12 一样在画面上 `Ctrl+Shift+C` 拾取元素,实时高亮 + 尺寸/坐标 tooltip,选中即写意见 |
| 3 | **意见文件 = 给 Agent 的接口** | 意见/字幕/配置**全部落盘成 JSON**,下一轮迭代直接读文件继续改(见 §二) |
| 4 | **审阅闭环的机检门禁** | 页面自检 / 缓存隔离审计 / 像素基线(见 §八) |

> **边界**:审片台是**开发期工具**,不是交付物。交付给用户的仍然是 mp4/PNG。
> 它也不改 artboard 的七步流水线:它是 Step 7 之后的**独立回路**。

## 一、起审片台

```bash
# 在项目根跑(--root 默认当前目录;页面地址会自动打印)
python <skill>/tools/review-station/review_station.py --root <项目>
python <skill>/tools/review-station/review_station.py --root <项目> --no-open   # CI/脚本友好
python <skill>/tools/review-station/review_station.py --stop                    # 收掉实例
```

页面 `http://127.0.0.1:8860/__rv/review.html`。**必须 http**(`file://` 会 CORS,保存全失败)。
运行期产物全在 `<项目>/review/`:意见.json / 字幕轨.json / 配置.json / 字幕导出 / 片段。
细则与 HTTP 契约见 `tools/review-station/README.md`。

> **为什么"改完直接在网页上审片"**【通用】:动效是时间的纯函数(页面里 `SEEK(t)`),
> 拖时间轴就是重算 —— 不必"渲片段 → 看成片"。一次出片要几十秒到几分钟,而审片要来回几十次;
> 真正需要出片的只有两种时候:① 要交给别人看的成片 ② 要 A/B 对照"预览与成片是否一致"。
> **这是审片台存在的全部理由**,也是它必须先有的前提:动效页要能被 `SEEK(t)` 驱动。

## 二、★ 意见文件即 Agent 接口(本册最重要的口径)

审片台上写的每条意见都落进 `<项目>/review/审片意见.json`:

```json
{
  "film": "片名或项目名",
  "note": "字段说明(工具写入,别删)",
  "updated": "2026-10-07 12:00:00",
  "notes": [
    { "id": "n1", "t0": 12.5, "t1": 12.5, "tag": "画面",
      "note": "这里字幕压住了主体", "fix": "字幕上移 24px 或延后 0.4s",
      "el": { "kind": "text", "label": ".sub span", "color": "#ff5a3c",
              "x": 540, "y": 902, "w": 420, "h": 38 } }
  ]
}
```

| 字段 | 含义 | 为什么有用 |
|---|---|---|
| `t0` / `t1` | 时间点 / 时间区间(秒);`t1 == t0` 表示"某一刻" | Agent 直接 `seek(t0)` 就能看到同一画面,不用问"大概几秒" |
| `note` | 用户的原话(不要润色) | 保留语感:"有点挤"和"溢出 8px"是两种改法 |
| `fix` | 用户给的建议(可空) | 有则照做,没有则按 `revision-protocol.md` 的**模糊愿望**流程诊断 |
| `el` | 元素拾取结果(可空) | **画布坐标**(不是屏幕坐标)+ 外观,Agent 能直接定位到代码里的那个元素 |
| `tag` | 分类(画面/字幕/音频/节奏…) | 决定改哪一层 |

**读法(Agent 侧,每轮改稿第一步)**:

1. 读 `<项目>/review/审片意见.json`;
2. 有 `el` 的按 `tag` + 坐标 + 外观**先在代码里定位**(别猜);没 `el` 的用 `t0` 逐帧看;
3. 按 `revision-protocol.md` 分档处置:明确指令 → 定点改;模糊愿望 → 诊断阶梯;
4. **改完把每条意见的状态回写**(`"done": true` 或另建 `审片意见.json` 的修订版),别默默改掉 ——
   下一轮用户还要对着同一条意见验。

> **这条口径的普适性**【通用】:它对海报、图文、长图同样成立 —— 任何"用户说不清哪里不满意"的场景,
> 只要把**位置 + 原话**落成文件,而不是靠对话历史里的一段转述,返修质量就完全不同。
> 这也是本册最值得先并入的一条(与 `revision-protocol.md` 的"模糊愿望翻译"天然配套)。

## 三、交互层通用铁律(改审片台 UI 时必守)

> 这一节的每一条都是**踩过才知道**的,且与视频无关 —— 做任何"网页上编辑内容再存盘"的
> 界面都适用(H5 互动页的后台、素材挑选页…)。

### 3.1 contenteditable 行内编辑的三条硬规则【通用】

1. **命中一律用 `closest(".rn")`**,不要用 `classList.contains("rn")`:光标落在浏览器
   自己插入的子元素(如 `<br>`、补位 `<span>`)上时后者漏判,原生行为就接管了;
2. **`Enter` 无条件 `preventDefault()`**(`Shift+Enter` 同样处理),然后自己决定语义;
3. **再挂 `beforeinput` 作权威通路**:`insertParagraph`/`insertLineBreak` = 拆句;
   `deleteContentBackward` 且光标在行首 = 并入上一句;keydown 里已处理的置标志跳过,
   `isComposing`(输入法组字中)一律不动。

### 3.2 保存层必须抗打(离线队列)【通用】

`Failed to fetch` 是**连接层**失败(服务没了 / `file://`),不是数据错。行为要这样定:

- POST 失败**不报错、进待写队列**,顶栏显示"服务已断开 · 待写 N 项";
- 每 2.5s 探活 `?action=ping`,恢复后**自动补写**;
- **队列存整份快照且按 URL 去重 ⇒ 重试幂等**;
- 服务端 `do_GET/do_POST` 顶层 try/except 一律回 `{ok:false,error}`,坏请求体当空 ——
  否则浏览器只看到"Failed to fetch",看不到原因;
- **localStorage 只在服务不可达时兜底**:恢复后无条件读本地档会把内存里的新编辑换成旧档。

### 3.3 唯一临时名(并发写的坑)【通用】

原子写的临时文件**必须唯一**(`tempfile.mkstemp`),不能固定成 `x.json.tmp`:
多线程/连发保存时两个线程会互相 `os.replace`,Windows 上撞 `EINVAL` 或"找不到文件",
用户看到的就是**莫名其妙"保存失败"**。

### 3.4 磁力吸附按**像素**换算【通用】

时间轴上的块头尾吸附:阈值写成秒是错的 —— 放大轨道后手感会变得极细或极粗。
一律 `SNAP_PX = 9px → 秒`(按当前缩放换算),尾吸下句开头、头吸上句结尾、整块平移吸任一侧。

### 3.5 缩放必须配一条平移滑条【通用】

只给"`Alt+滚轮` 缩放"必然出"放大后只能看一小段、没法跳"的抱怨。配套要齐:

- 平移滑条覆盖**整片 0 → DUR**,滑块宽度 = 视图跨度占比(**最小 20px**,否则抓不住),
  刻度显示播放头位置;
- 拖滑块按**抓取点**平移、点空白居中、滚轮按跨度平移、双击回全片;
- **平移不移动播放头**:视野是导航,不是定位(这一条最容易被写错)。

### 3.6 面板布局:flex 列分离"操作区 / 数据区"【通用】

两个 sticky 兄弟互相顶穿是必然的。三个列表页统一:

```css
.rv-panel.rv-flex { display: flex; flex-direction: column; overflow: hidden; }
.rv-freeze { position: static; flex: 0 0 auto; }      /* 冻结操作区 */
.rv-list   { flex: 1 1 auto; min-height: 140px; overflow-y: auto; }  /* 只有列表滚 */
```

**推论**:滑条的视觉位置应当是**状态的函数**,不要在交互中拦截状态→视觉同步
(拦截会让"播放中拖滑条"失效)。

### 3.7 别的成对/顺序类坑【通用】

- **拆 / 并必须互为逆操作**:并入 = 原样拼接**不补空格**;拆分 = 把词边界空格留在**前半段末尾**。
  只定义一侧,两个 bug 会互相掩盖 —— 只有"拆→并往返"不变量测试测得出来;
- **文本清洗的顺序即正确性**:`\s` 包含 `\n`,所以"归一空白"必须**排在**"生成换行"**之前**,
  且归一只能用 `[ \t]`(否则 `.ass` 的 `\N` 折行会被吃掉);
- **全局快捷键白名单必须含 `INPUT/SELECT/TEXTAREA/isContentEditable`**,
  且 `Ctrl+Z` 要在白名单**之前**单独拦(否则在字幕行里打字会触发"导出/全屏/渲片段");
- **同一个元素的事件只能一处赋值**:包装器覆盖了真 handler,是"按钮点了没反应"的头号原因;
- **`<select>` 设 `textContent` 会清空所有 `<option>`**:只动 `value`/`options`;
- **判断"元素是否显示"不能用 computed display**:父级 `display:none` 时子元素仍是 `block`,
  要用 `getBoundingClientRect().height > 0`;
- **短串替换长文件必须在副本上验证**:`content.replace('u"','"')` 会把 `$("au")` 截成 `$("a")`。

## 四、字幕:审片台自己的图层

**【通用】字幕绝不是画在影片 canvas 上的那一份。** 影片自己的歌词层(如果有)属于画面,
审片台的字幕是**另一层 DOM**(`#rv-sublayer`),固定底部安全区,可以随便调外观/位置/时间,
而不动画面一像素。数据优先读 `字幕轨.json`;**回写影片要由 Agent 做**(那是下一轮的事)。

### 4.1 解析三格式的坑(SRT / VTT / ASS)【通用】

- **按内容判别、扩展名兜底**:VTT 头是 `WEBVTT`;ASS 有 `[Script Info]`/`[V4+ Styles]`,
  字段顺序读 `[Events]` 的 `Format:` 行;**不能一上来就按逗号切**(不少 ASS 写的是
  SRT 风格的逗号毫秒,要先用正则摘出 layer/start/end);
- 时间戳正则要精确(`\d{1,3}:\d{1,2}:\d{1,2}(?:[.,]\d{1,3})?`),毫秒一律 `Math.round(t*1000)`;
- **解析出 0 条必须报警**:否则"切了没反应"会被当成界面坏了(这是最高频的误诊)。

### 4.2 字幕时长可以超片长,但导出按片长裁【通用】

编辑时给宽松天花板(`DUR + 3600s`),导出时前端发 `dur`,服务端:

- 结束时间截到 `dur`(截断计数);
- 整条落在片长之外 → 丢弃(丢弃计数);
- `WEBVTT`/`NOTE` 头部**原样保留不加序号**;坏时间码条目直接丢(否则产出编号重复的坏 SRT)。

## 五、诊断方法论【通用】(改稿阶段找"真凶"用)

1. **缩略图会骗人,必须上量化**(`numpy`,不是眼睛):"改了又跳"类反复,根因几乎都是
   用肉眼在缩略图上判断。常用指标:
   - 位移/跳帧 → 区域内**亮像素加权质心**逐帧漂移;
   - "像蒙了层滤镜" → **饱和度**(max−min)掉幅 + 过曝占比;
   - "真叠了罩子" → **背景区 RGB 逐值对照**(51,50,55 vs 50,49,55 ⇒ 没罩子,是自己白了);
   - "改动落在哪" → 分区差分热图;
2. **找真凶,不要改现象**:先量出指标,再拿指标去搜代码(反例:卡顿去调 GPU ——
   实测瓶颈是 CPU 端"每帧文本整形调用次数",正确解法是**少画/少渲染/别重复画**);
3. **量化之后才写铁律**:每条铁律都该能说出"当时的量化数据是什么";
4. 量完立刻写进 `docs/review/`(本地留档)或本册,别留在对话里。

## 六、MV 类动效的补强(模式 V 的长动效)

> 与 `video-motion.md`(片头/片尾/概括/章节的动效配方)配套:那一册解决"单件动效怎么做",
> 本册这一节解决"**多镜头长动效怎么组织、怎么核对、怎么查错**"。

### 6.1 音频 → 节拍 → 逐句时间轴(数据链)【通用】

| 环节 | 产物 | 说明 |
|---|---|---|
| 音频分析 | `audio.json` | 时长 / 采样率 / **bpm** / `beatPeriod` / `beats[]` / 能量包络 `energy[]`(低/高频分量 `low[]`/`high[]`)/ `accents[]` |
| 逐句时间轴 | `lyrics_timed.json` | `[{i, t, end, en}]`:序号、起、止、文本(92 句量级) |
| 字幕成品 | `*.srt` / `*.vtt` / `*.ass` | 中 / 英 / 中英对照三套;ASS 带样式 |

- **节拍 ≠ 句首**:artboard 的 `beat_sheet.py` 走"节拍/卡点"侧(MV 类动效的骨架),
  逐句时间轴走"歌词/字幕"侧 —— 两者互补,别互相替代;
- 换曲子必须**重跑音频分析族**,不要手改 `beats[]`(相位一错,整片卡点全歪);
- 卡点配动效的铁律:**只在节拍附近 0.04–0.08s 内做"变"(位移/显隐/换色)**,
  其余时间保持有呼吸的静止(见 `animation.md` 的动效词表)。

### 6.2 多镜头工程的三个组织原则【通用】

1. **内容与引擎分离**:引擎(合成/图层/fx)与内容(逐镜头脚本)分开。内容文件大而不拆
   (单文件 400KB 是常态,拆开只会增加跨文件跳转);
2. **加载顺序即依赖顺序**:页面里的 `<script>` 顺序就是真相源,别在别处再记一份;
3. **接缝层**:相邻镜头"同一件东西"的变化(相机、同一物件的参数)单独成一层,
   保证跨切口连续 —— **核对时先量成片里物体的绝对坐标,再看相机**,不要只核对物件参数。

### 6.3 时间窗判断:写 `sat((t-t0)/w)`,不要写 `t < t1`【通用】

"只在某时刻附近出现一下"的效果,一律:

```js
const q = sat((t - t0) / w);       // sat = clamp 到 [0,1]
if (q > 0.001 && q < 0.999) { /* 正在窗口内 */ }
```

反例(`if (t < 205.60)`)对所有 `t < 205.54` 都成立、`sat(负数) = 0`,于是"0.06s 的白闪"
变成"整 15 秒盖 30% 白"——**这类 bug 只能靠逐帧量化抓**(§五)。

### 6.4 缓存/加速开关只能影响预览【通用】

"少画/少渲染"的加速开关(抽稀、时间复用)**默认关闭**,且:

1. **焊死**:导出车道把开关设成只读常量,写一次再复查;
2. **默认值**必须是"全量";
3. **全量闸门**:暂停、逐帧、导出 PNG、悬停缩略图、成片 —— 全走全量绘制路径。

审计方式见 §八 的 `check_review_cache.py`(同一个 t 反复画,冷帧与暖帧必须**逐字节相同**)。

## 七、与 artboard 既有能力的重叠裁决(避免"双真相源")

来源资产包自己列的 4 处冲突,已按下面口径落地 —— **不要另起第二套**:

| # | 冲突点 | 裁决 |
|---|---|---|
| 1 | 节拍/BPM | 审片台**读 artboard 的节拍**(`beat_sheet.py` / `video-motion.md` 的卡点表),不自带第二套解析 |
| 2 | 像素比对 | `compare.py` 负责"两张图/两段视频的差异报告";审片台侧的 `check_px_baseline.py` 负责"**冻结基线 + 逐帧回归**"(改名以区分,见 §八) |
| 3 | 版面机检 | `check_overflow.py` 是**静态图的几何门禁**;`check_review_ui.py` 是**审片台页面自己的自检**,两层不合并、不改名 |
| 4 | 审阅标准 | `design-review-rubric.md` 是"人看的评分表";`docs/review/` 与审片台的回归断言是"机器跑的检查",互补 —— rubric 里已加指向回归脚本的一节 |

## 八、机检门禁(审片台侧三件)与已知限制

| 脚本 | 查什么 | 判据 |
|---|---|---|
| `check_review_ui.py` | 审片台页面自检:JS 引用的 id 在 HTML 里有没有 / 页签↔面板是否配对 / **审片台与影片页的 DOM 是否一致** | 无缺失即通过(纯正则,不用浏览器) |
| `check_review_cache.py` | 缓存隔离审计:同一 t 反复画(冷帧/暖帧/被加速开关污染后)是否**逐字节相同**;跨页对照是否只差"AA 级" | 页内 sha1 完全相同;跨页平均差 ≤2/255 且差>32 的像素 <6% |
| `check_px_baseline.py` | 成片像素基线:改动影片代码后出图是否与冻结基线一致 | 差异像素(通道差>8)占比 ≤0.05% 且最大通道差 ≤64 |

**量化的意义**:这三条都是"肉眼看不出来"的类别的判据 —— 页面静默半瘫、缓存污染、
时间相位型覆盖层(扫描线之类)导致的逐帧抖动。**判据要写进脚本,不要写在脑子里。**

**已知限制**(来源工程实测,别当 bug 追):

1. 字体缺失时预览退回系统字体,**不影响功能**,只影响观感(ASCII 网格类场景明显);
2. 无成片时"成片对照"为空、取帧不可用,**逐帧审片本身不依赖成片**;
3. 审片台是**单机单用户**工具:意见/字幕/配置是 JSON 文件,多人同时改会互相覆盖;
4. 逐帧导出的"参考帧"必须来自**成片**(不是预览页截图)——预览与成片的抗锯齿差一级,
   真出片一律以 `export.py` 为准。
